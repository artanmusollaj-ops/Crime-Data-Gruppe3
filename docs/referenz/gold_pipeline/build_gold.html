gold_pipeline.build_gold

Baut die Gold-Schicht: eine Faktentabelle und vier Dimensionen.

Aufruf aus dem Projekt-Root:

python -m gold_pipeline.build_gold

Warum kein Wuerfel gebaut wird, steht in gold_pipeline/__init__.py. Hier steht, was statt dessen entsteht und woran es haengt.

Die Stadtzuordnung ist der eigentliche Grund fuer diese Schicht. Bis hierher konnte das Projekt keine Rate je Einwohner belegen: silver/tract deckt ganze Countys ab, und ein Tract sagt nicht, zu welcher Stadt er gehoert. dim_tract beantwortet das ueber die Ortsgrenzen aus silver/place.

Tracts liegen dabei nicht sauber in Stadtgrenzen, sondern ueberschreiten sie. Drei Regeln waeren denkbar, und sie fallen weit auseinander:

Regel                     Chicago      Detroit
alle beruehrten Tracts    3'080'550    884'691
Flaechengewichtung        2'651'921    638'570
Mehrheitsregel            2'661'953    638'635
Zensus 2020               2'746'388    639'111

Gewaehlt ist die Mehrheitsregel: Ein Tract gehoert zu der Stadt, die mehr als die Haelfte seiner Flaeche bedeckt. Sie gibt jedem Tract genau eine Stadt - die Voraussetzung dafuer, dass sich Faelle ohne Doppelzaehlung summieren lassen - und liegt praktisch gleichauf mit der Flaechengewichtung. Der verbleibende Abstand zum Zensus ist keine Ungenauigkeit der Regel, sondern der Unterschied zwischen einer ACS-Schaetzung und einer Zaehlung.

Gruppiert wird ueber die amtliche Kategorie, nicht ueber das Praefix. dim_offense fuehrt nibrs_category aus dem NIBRS User Manual 2025.0 - 28 Group-A-Kategorien und 10 fuer Group B, gelesen von tools/build_nibrs_categories.py. Die Deliktfamilie (nibrs_family) bleibt daneben als Kuerzel 13, 23, 26 ohne Bezeichnung stehen: Die Spezifikation fuehrt dafuer keine auslesbare Liste, und eine selbst geschriebene waere eine gepflegte Uebersetzung mehr. Sie ist seit den Kategorien aber auch kein Auswertungsweg mehr, sondern ein technisches Praefix

 161    """Etwas, aus dem eine Gold-Tabelle abgeleitet ist.
 162

 164    versionierten CSV-Dateien unter ``config/`` - die Dimension traegt die
 165    ganze NIBRS-Klassifikation und muss sagen koennen, woher sie stammt.

 170    layer: str = SILVER_LAYER
 171    # Das Manifest der Quelle, damit Gold ihren **Stand** nennen kann und

 180def acs_vintages(text: str) -> tuple[int, ...]:
 181    """``2021,2022,2023,2024`` - aufsteigend, jedes einmal."""
 182    gefunden = set()
 183    for teil in text.split(","):
 184        teil = teil.strip()
 185        if not teil:
 186            continue
 187        try:
 188            gefunden.add(int(teil))
 189        except ValueError:
 190            raise argparse.ArgumentTypeError(
 191                f"{teil!r} ist kein Vintage"
 192            ) from None
 193    if not gefunden:
 194        raise argparse.ArgumentTypeError("kein Vintage angegeben")
 195    zu_neu = sorted(v for v in gefunden if v > NEWEST_VINTAGE)
 196    if zu_neu:
 197        raise argparse.ArgumentTypeError(
 198            f"{', '.join(str(v) for v in zu_neu)} gibt es nicht - das juengste "
 199            f"ACS-5-Jahres-Vintage ist {NEWEST_VINTAGE}"
 200        )
 201    return tuple(sorted(gefunden))

 236def silver_quelle(data_root: Path, name: str, vintage: int | None = None) -> Quelle:
 237    """Der Pfad einer Silver-Tabelle; mit Vintage, wo sie danach partitioniert ist.
 238
 239    Woher gelesen wird - lokal oder SeaweedFS - entscheidet die Ablage.
 240    """
 241    ablage = for_root(data_root)
 242    verzeichnis = f"{SILVER_LAYER}/dataset={name}"
 243    if vintage is not None:
 244        verzeichnis += f"/vintage={vintage}"
 245    if not ablage.exists(verzeichnis, PARQUET_FILE):
 246        treffer = ablage.list_files(verzeichnis, f"**/{PARQUET_FILE}")
 247        if not treffer:
 248            raise TransformError(
 249                f"Silver-Tabelle {name} fehlt unter {ablage.local_path(verzeichnis)}. "
 250                f"Zuerst bauen: python -m silver_pipeline.build_{name}"
 251            )
 252        verzeichnis = treffer[-1].rsplit("/", 1)[0]
 253    # Das Manifest wird mitgelesen: Gold soll sagen koennen, auf welchem
 254    # Silver-**Stand** es ruht - Zeitpunkt, Eingabe-Abdruck und dessen eigene
 255    # Herkunft. Ein Pfad allein zeigt nur auf das, was gerade dort liegt.
 256    manifest = {}
 257    if ablage.exists(verzeichnis, "manifest.json"):
 258        manifest = manifest_von(ablage, verzeichnis, "manifest.json")
 259    return Quelle(name, ablage.resolve_read_path(verzeichnis, PARQUET_FILE),
 260                  manifest=manifest)

 268def dim_tract_query(tract: Quelle, place: Quelle, vintage: int) -> str:
 269    """Ordnet jeden Tract der Stadt zu, die mehr als seine halbe Flaeche deckt.
 270
 271    Der Join ist ein innerer auf ``ST_Intersects`` und danach eine Fensterfunktion:
 272    Ein Tract kann an beide Staedte grenzen - Chicago und Detroit liegen zwar
 273    weit auseinander, aber die Regel darf davon nicht abhaengen. Genommen wird
 274    der groesste Anteil, und nur wenn er ueber der Schwelle liegt.
 275    """
 276    staedte = ", ".join(
 277        f"('{geoid}', '{schluessel}')"
 278        for geoid, schluessel in sorted(STADT_SCHLUESSEL.items())
 279    )
 280    return f"""
 281    WITH studienstadt(city_geoid, city) AS (VALUES {staedte}),
 282    grenze AS (
 283        SELECT s.city_geoid, s.city, ST_GeomFromWKB(p.geometry) AS geom
 284        FROM {place.relation} p
 285        JOIN studienstadt s ON s.city_geoid = p.geoid
 286    ),
 287    anteil AS (
 288        SELECT
 289            t.geoid,
 290            g.city_geoid,
 291            g.city,
 292            ST_Area(ST_Intersection(ST_GeomFromWKB(t.geometry), g.geom))
 293                / nullif(ST_Area(ST_GeomFromWKB(t.geometry)), 0) AS flaechenanteil
 294        FROM {tract.relation} t
 295        JOIN grenze g ON ST_Intersects(ST_GeomFromWKB(t.geometry), g.geom)
 296    ),
 297    beste AS (
 298        SELECT * FROM (
 299            SELECT *, row_number() OVER (
 300                PARTITION BY geoid ORDER BY flaechenanteil DESC
 301            ) AS rang
 302            FROM anteil
 303        ) WHERE rang = 1
 304    )
 305    SELECT
 306        t.geoid                                         AS geoid,
 307        CASE WHEN b.flaechenanteil > {STADT_SCHWELLE}
 308             THEN b.city END                            AS city,
 309        CASE WHEN b.flaechenanteil > {STADT_SCHWELLE}
 310             THEN b.city_geoid END                      AS city_geoid,
 311        -- Auch unterhalb der Schwelle festgehalten: Wer flaechengewichtet
 312        -- rechnen will, braucht den Anteil, und wer die Regel pruefen will
 313        -- auch. Ohne Beruehrung ist er 0 und nicht NULL.
 314        coalesce(b.flaechenanteil, 0.0)                 AS city_area_share,
 315        t.state_fips                                    AS state_fips,
 316        t.state_name                                    AS state_name,
 317        t.county_fips                                   AS county_fips,
 318        t.name                                          AS tract_name,
 319        -- Welchem Vintage die Stadtzuordnung und die Geometrie entstammen.
 320        -- Sie werden **nicht** je Jahrgang neu gerechnet: Ein Tract soll
 321        -- dauerhaft eine Stadt haben, sonst springt eine Rate aus einem Grund,
 322        -- der nichts mit Kriminalitaet zu tun hat. Die Einwohnerzahlen liegen
 323        -- dagegen je Vintage - in dim_tract_acs.
 324        CAST({vintage} AS SMALLINT)                     AS reference_vintage,
 325        t.land_area_m2                                  AS land_area_m2,
 326        t.centroid_lat                                  AS centroid_lat,
 327        t.centroid_lon                                  AS centroid_lon
 328    FROM {tract.relation} t
 329    LEFT JOIN beste b ON b.geoid = t.geoid
 330    ORDER BY geoid
 331    """

 334#: Douglas-Peucker in Grad - rund zwei Meter.
 335#:
 336#: **Hier und nicht in ``serving``.** Bis zum 14.10.2026 stand die Zahl allein
 337#: in ``export_geojson``; seit ``dim_tract_geo`` vereinfacht Gold selbst, und
 338#: zwei Toleranzen nebeneinander hiessen: Die Karte in Kibana und die Karte im
 339#: Browser zeigen verschieden genaue Umrisse, ohne dass es jemandem auffiele.
 340#: ``export_geojson`` liest die Zahl deshalb von hier.
 341#:
 342#: Gemessen (Tabelle im Modulkopf von ``serving.export_geojson``): 2,94 MB auf
 343#: 0,55 MB, und die Flaeche je Tract verliert 0,0002 Prozent. Der ganze Gewinn
 344#: liegt in den ersten zwei Metern - fuenfmal groeber spart noch 0,13 MB.
 345VEREINFACHUNG_GRAD = 0.00002
 346
 347
 348def dim_tract_geo_query(tract: Quelle) -> str:
 349    """Der Umriss je Tract der beiden Studienstaedte - als WKT.
 350
 351    **Warum eine eigene Tabelle und keine Spalte an ``dim_tract``.** Die
 352    Dimension deckt beide Countys ab, 6'282 Zeilen; mit Umrissen in voller
 353    TIGER-Genauigkeit waere sie 26 MB statt 194 KB, und jedes ``SELECT *``
 354    schleppte sie mit (``serving.export_geojson`` nennt genau diesen Grund).
 355    Diese Tabelle traegt nur die **1'055 Tracts mit Stadt** und nur den
 356    vereinfachten Umriss: 0,5 MB.
 357
 358    **Warum WKT und nicht WKB oder GeoJSON.** Elasticsearch nimmt fuer
 359    ``geo_shape`` eine WKT-Zeichenkette unmittelbar an. WKB muesste der Lader
 360    erst wandeln, und GeoJSON muesste er als Objekt einbetten statt als Wert
 361    durchzureichen - beides waere eine Gabelung in einem Lader, der jede
 362    Spalte gleich behandelt.
 363
 364    **Warum ``city`` mitfaehrt.** Damit die Karte nach Stadt filtern kann,
 365    ohne fuer jede Flaeche nach ``dim_tract`` zurueckzuspringen. Eine
 366    Einwohnerzahl oder gar eine Rate steht hier **nicht**: Die waere eine
 367    zweite Wahrheit, die veraltet, ohne dass man es ihr ansieht.
 368    """
 369    return f"""
 370    SELECT
 371        d.geoid,
 372        d.city,
 373        d.tract_name,
 374        ST_AsText(ST_Simplify(ST_GeomFromWKB(t.geometry),
 375                              {VEREINFACHUNG_GRAD})) AS boundary_wkt
 376    FROM {tract.relation} t
 377    JOIN dim_tract d ON d.geoid = t.geoid
 378    WHERE t.geometry IS NOT NULL AND d.city IS NOT NULL
 379    ORDER BY d.geoid
 380    """

 383def dim_tract_acs_query(tracts: dict[int, Quelle]) -> str:
 384    """Die ACS-Masse je Tract **und Vintage** - der Nenner jeder Rate.
 385
 386    Bis zum 3.10.2026 standen ``population``, Einkommen und Armutsquote in
 387    ``dim_tract``, und das ging nur, solange es einen einzigen Jahrgang gab:
 388    Eine Tabelle mit einer Zeile je Tract kann nur eine Einwohnerzahl tragen.
 389    Ueber sechs Jahrgaenge haette jede Tat denselben Nenner bekommen, auch die
 390    von 2021 - und das Ergebnis saehe vollstaendig aus.
 391
 392    Die Masse liegen deshalb hier, je Vintage, und ``fact_offense`` nennt mit
 393    ``population_vintage``, welches davon fuer seine Zeile gilt. Verbunden wird
 394    ueber beide Spalten. Wer nur ``geoid`` verbindet, bekommt je Tract so viele
 395    Zeilen, wie Vintages geladen sind - deshalb steht die Warnung auch im
 396    Feldkatalog.
 397
 398    ``dim_tract`` behaelt die Spalten, die kein Vintage haben: Stadtzuordnung,
 399    Flaechenanteil, Name, Flaeche, Schwerpunkt. Sie waren vorher mit den Massen
 400    in einer Tabelle, was keine Dopplung war, sondern eine Vermischung.
 401    """
 402    teile = []
 403    for vintage, quelle in sorted(tracts.items()):
 404        teile.append(f"""
 405    SELECT
 406        t.geoid                                         AS geoid,
 407        CAST({vintage} AS SMALLINT)                     AS vintage,
 408        t.population                                    AS population,
 409        t.median_household_income_usd                   AS median_household_income_usd,
 410        t.poverty_rate                                  AS poverty_rate
 411    FROM {quelle.relation} t""")
 412    return "\nUNION ALL\n".join(teile) + "\n    ORDER BY vintage, geoid\n"

 421    """Die amtliche NIBRS-Codeliste, plus die Codes, die nur noch die Daten kennen.
 422
 423    Vier NIBRS-Codes hat das FBI zurueckgezogen; die MICR-Quellen von 2009 und
 424    2024 fuehren sie weiter, und zwei davon stehen in den Falldaten 2024 -
 425    ``90I Runaway`` mit 969 und ``90A Bad Checks`` mit 50 Faellen. Stuenden sie
 426    nicht in dieser Dimension, wuerde jede Auswertung, die ueber sie filtert,
 427    1'019 Delikte stillschweigend verlieren. Genau diese Art von Verlust soll
 428    ein Sternschema verhindern und nicht verursachen.
 429
 430    Sie werden deshalb aufgenommen und als ``retired`` gekennzeichnet. Ihre
 431    Bezeichnung stammt aus den Crosswalks, die sie noch fuehren - nicht aus der
 432    Spezifikation, die sie nicht mehr kennt.
 433    """
 434    pfad = config_root / NIBRS_CODES
 435    if not pfad.exists():
 436        raise TransformError(f"Codeliste fehlt: {pfad}")
 437    with pfad.open(encoding="utf-8") as datei:
 438        amtlich = list(csv.DictReader(datei))
 439    if not amtlich:
 440        raise TransformError(f"Codeliste ist leer: {pfad}")
 441
 442    kat_pfad = config_root / NIBRS_KATEGORIEN
 443    if not kat_pfad.exists():
 444        raise TransformError(
 445            f"Kategorienliste fehlt: {kat_pfad}. "
 446            "Zuerst: python tools/build_nibrs_categories.py"
 447        )
 448    with kat_pfad.open(encoding="utf-8") as datei:
 449        kategorie = {z["nibrs_code"]: z["nibrs_category"] for z in csv.DictReader(datei)}
 450
 451    ohne_kategorie = sorted(
 452        z["nibrs_code"] for z in amtlich if z["nibrs_code"] not in kategorie
 453    )
 454    if ohne_kategorie:
 455        raise TransformError(
 456            f"Codes ohne Kategorie: {ohne_kategorie} - "
 457            "tools/build_nibrs_categories.py neu laufen lassen"
 458        )
 459
 460    zeilen = []
 461    for z in amtlich:
 462        code = z["nibrs_code"]
 463        ersatz, aufloesung, grund = UMGESCHLUESSELT.get(code, (None, "current", None))
 464        zeilen.append({
 465            "nibrs_code": code,
 466            "nibrs_description": z["nibrs_description"],
 467            "nibrs_category": kategorie[code],
 468            "nibrs_family": code[:2],
 469            "nibrs_group": z["nibrs_group"],
 470            "crime_against": z["crime_against"],
 471            "federal_only": z["federal_only"] == "true",
 472            "retired": False,
 473            "replaced_by": ersatz,
 474            "resolution": aufloesung,
 475            "retirement_note": grund,
 476        })
 477
 478    bekannt = {z["nibrs_code"] for z in zeilen}
 479    for name in CROSSWALKS:
 480        quelle = config_root / name
 481        if not quelle.exists():
 482            continue
 483        with quelle.open(encoding="utf-8") as datei:
 484            for z in csv.DictReader(datei):
 485                code = (z.get("nibrs_code") or z.get("ibr_code") or "").strip()
 486                if not code or code in bekannt:
 487                    continue
 488                bekannt.add(code)
 489                ersatz, aufloesung, grund = ZURUECKGEZOGEN.get(
 490                    code, (None, "unresolved", "kein Beleg hinterlegt")
 491                )
 492                zeilen.append({
 493                    "nibrs_code": code,
 494                    "nibrs_description": (
 495                        z.get("nibrs_description") or z.get("ibr_category") or ""
 496                    ).strip(),
 497                    "nibrs_category": kategorie.get(code, ""),
 498                    "nibrs_family": code[:2],
 499                    "nibrs_group": (z.get("nibrs_group") or "B").strip() or "B",
 500                    "crime_against": "",
 501                    "federal_only": False,
 502                    "retired": True,
 503                    "replaced_by": ersatz,
 504                    "resolution": aufloesung,
 505                    "retirement_note": grund,
 506                })
 507    return sorted(zeilen, key=lambda z: z["nibrs_code"])

 510def dim_date_query(offense: Quelle) -> str:
 511    """Ein Kalendertag je Zeile, ueber die Spanne der Falldaten.
 512
 513    Erzeugt wird die Reihe und nicht aus den Fakten abgeleitet: Ein Tag ohne
 514    Delikt ist eine Aussage und darf nicht fehlen, sonst zeigt eine Zeitreihe
 515    eine Luecke als Nicht-Ereignis.
 516    """
 517    return f"""
 518    WITH spanne AS (
 519        SELECT min(occurred_date_local) AS von, max(occurred_date_local) AS bis
 520        FROM {offense.relation}
 521    )
 522    -- generate_series liefert auf DATE-Grenzen TIMESTAMP zurueck. Ohne den
 523    -- Cast traegt die Dimension einen anderen Typ als der Schluessel in
 524    -- fact_offense, und der Join haengt an einer stillschweigenden Umwandlung.
 525    SELECT
 526        CAST(tag AS DATE)                               AS date,
 527        -- Schmale Typen, weil die Sache schmal ist: ein Jahr passt in
 528        -- SMALLINT, alles Uebrige in TINYINT (-128 bis 127). DuckDBs
 529        -- Datumsfunktionen liefern durchweg BIGINT; ohne CAST stuende in
 530        -- einer Dimensionstabelle achtmal so viel Platz wie noetig.
 531        CAST(year(tag) AS SMALLINT)                     AS year,
 532        CAST(month(tag) AS TINYINT)                     AS month,
 533        CAST(quarter(tag) AS TINYINT)                   AS quarter,
 534        CAST(day(tag) AS TINYINT)                       AS day_of_month,
 535        CAST(dayofweek(tag) AS TINYINT)                 AS day_of_week,
 536        dayname(tag)                                    AS day_name,
 537        monthname(tag)                                  AS month_name,
 538        CAST(date_trunc('month', tag) AS DATE)          AS month_start,
 539        dayofweek(tag) IN (0, 6)                        AS is_weekend,
 540        CAST(dayofyear(tag) AS SMALLINT)                AS day_of_year,
 541        -- FR-37: Ob der Jahrgang dieses Tages **ganz** in den Daten liegt.
 542        -- Ein Teiljahr darf nicht in einen Jahresvergleich geraten: 2026 hat
 543        -- am 3.10. neun Monate, und neun Monate gegen zwoelf gestellt ergeben
 544        -- einen Rueckgang, den es nicht gibt. Die Spanne steht schon in
 545        -- ``spanne`` - gefragt ist nur, ob sie den 1.1. und den 31.12. dieses
 546        -- Jahres einschliesst. Eine Luecke **innerhalb** des Jahres faellt
 547        -- damit nicht auf; die misst der Nachweis je Jahrgang (FR-39).
 548        (s.von <= make_date(year(tag), 1, 1)
 549         AND s.bis >= make_date(year(tag), 12, 31))    AS year_is_complete
 550    FROM spanne s, unnest(generate_series(s.von, s.bis, INTERVAL 1 DAY)) AS t(tag)
 551    ORDER BY date
 552    """

 555def dim_city_day_query(weather: Quelle, offense: Quelle) -> str:
 556    """Stadt und Tag mit dem Wetter, auf die Spanne der Falldaten beschnitten.
 557
 558    Die Wetterquelle reicht bis 1942 zurueck. Fuer Gold zaehlt der Jahrgang,
 559    den die Falldaten abdecken; alles andere blaeht die Dimension auf, ohne
 560    eine Frage zu beantworten.
 561
 562    **Warum die beiden Spurenspalten mitkommen.** NOAA kennt ein Messflag
 563    ``T``: gefallen, aber unter der Aufloesung des Geraets. Der Messwert ist
 564    dann ``0``, und das heisst etwas anderes als *trocken*. Silver haelt den
 565    Unterschied seit jeher in ``precipitation_trace`` und ``snowfall_trace``;
 566    Gold liess beide Spalten bis zum 15.9.2026 fallen.
 567
 568    Gemessen war das keine Feinheit: Von den 481 Gold-Tagen mit ``0`` mm
 569    Niederschlag sind **113 Spurentage** - 45 in Chicago, 68 in Detroit. Eine
 570    Abfrage nach trockenen Tagen zaehlte sie mit, und niemand konnte es der
 571    Tabelle ansehen. Konzept 9.3 verlangt ausdruecklich, dass die
 572    Spurenmengen in Gold erhalten bleiben.
 573    """
 574    return f"""
 575    WITH spanne AS (
 576        SELECT min(occurred_date_local) AS von, max(occurred_date_local) AS bis
 577        FROM {offense.relation}
 578    )
 579    SELECT
 580        w.city                                          AS city,
 581        w.date                                          AS date,
 582        w.station_id                                    AS station_id,
 583        w.station_name                                  AS station_name,
 584        w.temp_max_c                                    AS temp_max_c,
 585        w.temp_min_c                                    AS temp_min_c,
 586        w.precipitation_mm                              AS precipitation_mm,
 587        w.snowfall_mm                                   AS snowfall_mm,
 588        w.precipitation_trace                           AS precipitation_trace,
 589        w.snowfall_trace                                AS snowfall_trace,
 590        w.quality_flags                                 AS quality_flags
 591    FROM {weather.relation} w, spanne
 592    WHERE w.date BETWEEN spanne.von AND spanne.bis
 593    ORDER BY city, date
 594    """

 602def fact_offense_query(offense: Quelle, tracts: str = "dim_tract", *,
 603                       vintages: tuple[int, ...] = (NEWEST_VINTAGE,)) -> str:
 604    """Eine Zeile je **Tat**, mit den Schluesseln der Dimensionen.
 605
 606    Hier liegt der einzige Stellenwechsel gegenueber Silver. Detroits Zeilen
 607    sind **Anklagen**, Chicagos sind **Delikte**: Ein Ueberfall mit Schuessen
 608    und geraubtem Auto steht bei Detroit als fuenf Zeilen, bei Chicago als
 609    eine. Wer beide summiert, zaehlt Detroit um 3,8 Prozent zu hoch.
 610
 611    Silver haelt deshalb jede Anklage und markiert je Tat eine Zeile mit
 612    ``counts``; Gold nimmt nur diese. Wer die Anklagen braucht - "wie oft wurde
 613    zusaetzlich Sachbeschaedigung angezeigt" -, findet sie vollstaendig in
 614    ``silver/crime_offense``.
 615
 616    Dazu kommt ``counts_case`` unveraendert aus Silver: je **Fall** eine Zeile,
 617    die mit dem schwersten Delikt. Chicago fuehrt je Vorfall ein Delikt,
 618    Detroit jedes - auf Tatebene zaehlt Detroit 6,4 Prozent, die Chicago nie
 619    zaehlt. Wer beide Staedte auf Chicagos Zaehlweise vergleichen will, filtert
 620    auf ``counts_case``; die Tatzahlen bleiben, wie sie sind.
 621
 622
 623    Ergaenzt werden nur Groessen, die sich aus dem Zeitstempel ableiten, und die
 624    Deliktfamilie. Sie sparen keine Laufzeit - gemessen 0,3 Millisekunden -,
 625    sondern ersparen jeder Abfrage das Wissen, dass die Familie die ersten
 626    beiden Zeichen des Codes sind.
 627
 628    **Die Reihenfolge ist Teil des Ergebnisses.** Ohne ``ORDER BY`` entscheidet
 629    sie der Hash-Join und die Zahl der Threads: Am 4.10.2026 gemessen lagen
 630    zwischen zwei Laeufen in getrennten Prozessen **245'760 von 345'091 Zeilen**
 631    an anderer Position - 71 Prozent der Tabelle, bei identischen
 632    Zeilengruppengrenzen. Die Dateigroesse schwankte dabei zwischen Aufrufen
 633    (14'947'218 bis 15'001'199 Bytes gemessen) und war in einem Paar sogar
 634    gleich, waehrend die Bytes abwichen - eine gleiche Groesse beweist hier also
 635    nichts. ``serving.pruefe_stand`` meldete Gold nach jedem Neubau als
 636    "anders", obwohl kein Wert sich geaendert hatte; das Erfolgskriterium
 637    "zweiter Lauf, gleiche Pruefsummen" war fuer Gold nicht erfuellt.
 638
 639    Sortiert wird nach ``date`` und dann ``offense_id``. Der Tag ist die Achse,
 640    auf der am meisten gefiltert wird - so kann die Zeilengruppenstatistik
 641    greifen -, und die Kennung macht die Ordnung eindeutig. Der sortierte Stand
 642    reproduziert sich exakt bei **15'808'123 Bytes**; gegen die schwankende
 643    unsortierte Spanne sind das 5,4 bis 5,8 Prozent mehr Platz, bei keiner
 644    messbaren Zeit. ``ORDER BY offense_id`` allein waere rund 7,7 Prozent
 645    gewesen.
 646
 647    Diese Abfrage war die **einzige der Strecke ohne Reihenfolge**. Vier
 648    Dimensionsabfragen haben eine - ``dim_tract``, ``dim_tract_acs``,
 649    ``dim_date``, ``dim_city_day`` -, ``build_crime_offense.build_query`` endet
 650    mit ``ORDER BY b.city, b.occurred_at_utc, b.offense_id``, und
 651    ``serving.build_comparison`` ebenso. ``dim_offense`` entsteht nicht aus
 652    einer Abfrage, sondern aus ``CREATE TABLE`` plus ``executemany``; seine
 653    Reihenfolge ist die der Codeliste.
 654    """
 655    aeltestes, neuestes = min(vintages), max(vintages)
 656    return f"""
 657    SELECT
 658        o.offense_id                                    AS offense_id,
 659        o.event_id                                      AS event_id,
 660        o.city                                          AS reporting_city,
 661        o.occurred_at_utc                               AS occurred_at_utc,
 662        o.occurred_at_local                             AS occurred_at_local,
 663        o.occurred_date_local                           AS date,
 664        CAST(hour(o.occurred_at_local) AS TINYINT)      AS hour_of_day,
 665        -- Genau hier wird die Spalte gebraucht: Eine Stundenverteilung ueber
 666        -- hour_of_day zaehlt eine mehrdeutige Ortszeit in einen der beiden
 667        -- Toepfe, und ohne diese Spalte ist nicht zu sehen, welche Zeilen das
 668        -- betrifft. Chicago liefert Wanduhrzeit ohne Zone; 48 Zeilen liegen in
 669        -- der Stunde, die es am 3.11.2024 zweimal gab.
 670        o.local_time_ambiguous                          AS local_time_ambiguous,
 671        o.tract_geoid                                   AS tract_geoid,
 672        -- Welcher ACS-Jahrgang der Nenner dieser Zeile ist. Fuer 2021 bis
 673        -- 2024 das eigene Jahr, darueber der juengste vorhandene: Eine Rate
 674        -- fuer 2025 ruht auf der Bevoelkerung von 2024, und das steht hier in
 675        -- den Daten statt in einer Fussnote (FR-36). Geklammert wird auf die
 676        -- geladene Spanne, damit die Zeile auf eine Zeile in dim_tract_acs
 677        -- zeigt und nicht ins Leere.
 678        CAST(greatest(least(year(o.occurred_date_local), {neuestes}),
 679                      {aeltestes}) AS SMALLINT)         AS population_vintage,
 680        o.nibrs_code                                    AS nibrs_code,
 681        left(o.nibrs_code, 2)                           AS nibrs_family,
 682        o.source_offense_code                           AS source_offense_code,
 683        o.source_offense_description                    AS source_offense_description,
 684        o.latitude                                      AS latitude,
 685        o.longitude                                     AS longitude,
 686        o.located                                       AS located,
 687        o.mapping_status                                AS mapping_status,
 688        -- Warum eine Zeile in einer Tract-Auswertung fehlt, in einem Wort.
 689        -- ``located`` sagt nur ja oder nein; hier steht der Grund, und die
 690        -- vierte Stufe braucht die Stadtgrenze - deshalb entsteht die Spalte
 691        -- in Gold und nicht in Silver.
 692        CASE
 693            WHEN o.latitude IS NULL   THEN 'missing_coordinate'
 694            WHEN o.tract_geoid IS NULL THEN 'no_tract'
 695            WHEN t.city IS NULL        THEN 'outside_city'
 696            ELSE 'inside_city'
 697        END                                             AS geo_status,
 698        o.arrest                                        AS arrest,
 699        o.unfounded                                     AS unfounded,
 700        o.offense_group_id                              AS offense_group_id,
 701        o.counts_case                                   AS counts_case
 702    FROM {offense.relation} o
 703    LEFT JOIN {tracts} t ON t.geoid = o.tract_geoid
 704    WHERE o.counts
 705    ORDER BY date, offense_id
 706    """

 714def abdeckung(con: duckdb.DuckDBPyConnection) -> dict[str, float]:
 715    """Misst, wie sich die Fakten auf die beiden Statusspalten verteilen.
 716
 717    Nur messen - ob die Anteile ausreichen, entscheidet ``pruefe_gate``. Die
 718    Trennung ist Absicht: Eine Messung darf auch dann Zahlen liefern, wenn sie
 719    schlecht aussehen, und eine Testfixture mit zwei Zeilen hat naturgemaess
 720    schraege Anteile.
 721
 722    Eine Pruefung steckt trotzdem hier, weil sie keine Ermessensfrage ist:
 723    Kommt in ``mapping_status`` oder ``geo_status`` ein Wert vor, den der Code
 724    nicht kennt, hat jemand die Einstufung geaendert - dann bleibt der Bau
 725    stehen, statt eine Kennzahl still zu verschieben.
 726    """
 727    unbekannt = {}
 728    for spalte, erlaubt in (("mapping_status", MAPPING_STATUS_WERTE),
 729                            ("geo_status", GEO_STATUS_WERTE)):
 730        fremd = sorted(
 731            str(z[0]) for z in con.execute(
 732                f"SELECT DISTINCT {spalte} FROM fact_offense"
 733            ).fetchall() if z[0] not in erlaubt
 734        )
 735        if fremd:
 736            unbekannt[spalte] = fremd
 737    if unbekannt:
 738        raise TransformError(
 739            f"Unbekannte Statuswerte in fact_offense: {unbekannt}. Entweder "
 740            "ist die Einstufung geaendert worden - dann gehoert der neue Wert "
 741            "in MAPPING_STATUS_WERTE beziehungsweise GEO_STATUS_WERTE - oder "
 742            "es ist ein Tippfehler."
 743        )
 744
 745    gesamt = con.execute("SELECT count(*) FROM fact_offense").fetchone()[0]
 746    anteile: dict[str, float] = {}
 747    for spalte, werte in (("geo_status", GEO_STATUS_WERTE),
 748                          ("mapping_status", MAPPING_STATUS_WERTE)):
 749        for wert in sorted(werte):
 750            n = con.execute(
 751                f"SELECT count(*) FROM fact_offense WHERE {spalte} = ?", [wert]
 752            ).fetchone()[0]
 753            anteile[wert] = round(100.0 * n / gesamt, 4) if gesamt else 0.0
 754
 755    return anteile

 758def jahresabdeckung(con: duckdb.DuckDBPyConnection) -> dict[str, dict[str, Any]]:
 759    """Was je Jahrgang abgedeckt ist - und was fehlt (FR-39).
 760
 761    ``year_is_complete`` in ``dim_date`` sagt nur, ob die Spanne den 1.1. und
 762    den 31.12. einschliesst. Eine Luecke **innerhalb** des Jahres sieht man
 763    daran nicht: Ein Jahrgang, dem der halbe Juli fehlt, bleibt dort "ganz".
 764    Deshalb stehen hier beide Zahlen - ``days_with_offenses`` gegen
 765    ``days_in_year``. Wer eine Zeitreihe baut, braucht die zweite.
 766
 767    ``days_with_offenses`` zaehlt Tage mit mindestens einer Tat. Bei zwei
 768    Grossstaedten ist jeder Tag besetzt; faellt die Zahl unter die Tage des
 769    Jahres, fehlt wirklich etwas.
 770    """
 771    return {
 772        str(z[0]): {
 773            "offenses": z[1],
 774            "first_date": z[2].isoformat() if z[2] else None,
 775            "last_date": z[3].isoformat() if z[3] else None,
 776            "days_with_offenses": z[4],
 777            "days_in_year": z[5],
 778            "complete": bool(z[6]),
 779        }
 780        for z in con.execute("""
 781            SELECT d.year,
 782                   count(f.offense_id),
 783                   min(f.date),
 784                   max(f.date),
 785                   count(DISTINCT f.date),
 786                   CAST(dayofyear(make_date(d.year, 12, 31)) AS INTEGER),
 787                   any_value(d.year_is_complete)
 788            FROM dim_date d LEFT JOIN fact_offense f ON f.date = d.date
 789            GROUP BY d.year ORDER BY d.year
 790        """).fetchall()
 791    }

 794def abdeckung_je_stadt(con: duckdb.DuckDBPyConnection) -> dict[str, dict[str, float]]:
 795    """Dieselben Anteile, aber je meldender Stadt.
 796
 797    **Warum das noetig ist.** Der Gesamtanteil ist ein Mittel, und ein Mittel
 798    verdeckt. Eine externe Pruefung hat das am 15.9.2026 vorgerechnet: 750
 799    Chicagoer Zeilen zu 100 % exakt und 250 Detroiter zu 70 % ergeben 92,5 %
 800    gemeinsam - bestanden, bei einer Schwelle von 85 %. Detroits Crosswalk
 801    haette also zu einem Drittel brechen koennen, ohne dass etwas rot wird.
 802
 803    Chicago ist dreimal so gross wie Detroit. Genau deshalb traegt der
 804    Gesamtanteil Chicagos Zahl und nicht Detroits.
 805    """
 806    zeilen = con.execute("""
 807        SELECT reporting_city, geo_status, mapping_status, count(*)
 808        FROM fact_offense GROUP BY 1, 2, 3
 809    """).fetchall()
 810    gesamt: dict[str, int] = {}
 811    treffer: dict[str, dict[str, int]] = {}
 812    for stadt, geo, mapping, n in zeilen:
 813        gesamt[stadt] = gesamt.get(stadt, 0) + n
 814        je = treffer.setdefault(stadt, {})
 815        for wert in (geo, mapping):
 816            je[wert] = je.get(wert, 0) + n
 817
 818    ergebnis: dict[str, dict[str, float]] = {}
 819    for stadt, n_gesamt in sorted(gesamt.items()):
 820        je = treffer.get(stadt, {})
 821        ergebnis[stadt] = {
 822            wert: round(100.0 * je.get(wert, 0) / n_gesamt, 4) if n_gesamt else 0.0
 823            for wert in sorted(set(GEO_STATUS_WERTE) | set(MAPPING_STATUS_WERTE))
 824        }
 825    return ergebnis

 828def zuordnung_je_jahrgang(
 829    con: duckdb.DuckDBPyConnection,
 830) -> dict[str, dict[str, Any]]:
 831    """Wie die NIBRS-Zuordnung je Jahrgang traegt - und was sich bewegt hat (FR-38).
 832
 833    ``abdeckung`` misst ueber die **ganze** Faktentabelle, ``abdeckung_je_stadt``
 834    je Stadt. Beides ist ueber die Zeit gemittelt, und ein Mittel verdeckt:
 835    Ueber sechs Jahrgaenge verschwindet ein schlechter im Durchschnitt der
 836    uebrigen. Ein Crosswalk, der ab 2026 ins Leere laeuft, bliebe bei einer
 837    Schwelle von 85 % unsichtbar, solange die fuenf Jahrgaenge davor tragen -
 838    dasselbe Argument, mit dem ``abdeckung_je_stadt`` entstand, nur auf der
 839    Zeitachse.
 840
 841    Dies ist **Zuordnungs**abdeckung und steht deshalb neben
 842    ``jahresabdeckung`` und nicht darin: jene misst, welche *Tage* abgedeckt
 843    sind, diese, welche *Quellcodes* einen NIBRS-Code bekamen.
 844
 845    Drei Dinge nennt der Nachweis **namentlich**, weil ein Prozentsatz sie
 846    nicht sagt:
 847
 848    ``unmapped_codes``       welcher Quellcode unzugeordnet blieb, mit Stadt
 849                             und Zahl, absteigend - der teuerste zuerst
 850    ``new_source_codes``     welcher Code im Vorjahrgang nicht vorkam
 851    ``retired_source_codes`` welcher im Vorjahrgang vorkam und jetzt fehlt
 852
 853    Die Stadt steht ueberall dabei, weil derselbe vierstellige Code in beiden
 854    Staedten etwas voellig anderes bedeutet: ``1101`` ist in Chicagos IUCR
 855    *Public Aid Wire/Mail Fraud* und fuehrt auf 26D Welfare Fraud, in Detroits
 856    MICR *Sexual Penetration Penis/Vagina CSC1* und fuehrt auf 11A Rape. Sieben
 857    Codes stehen in beiden Tabellen (``1101``, ``1102``, ``1200``, ``2900``,
 858    ``4800``, ``5000``, ``5001``); ohne die Stadt ist keine Zeile der Liste
 859    aufloesbar.
 860
 861    **Ein Teiljahrgang wird gemeldet, aber nicht verglichen.** Fuer einen
 862    Jahrgang mit ``year_is_complete = false`` bleiben beide Codelisten leer,
 863    und der Vergleich ueberspringt ihn: Der naechste **volle** Jahrgang
 864    vergleicht gegen den letzten vollen. 2026 hat am 3.10. neun Monate - jeder
 865    Code, der dort nur noch nicht vorkam, waere sonst "weggefallen". Das ist
 866    dieselbe Regel, die FR-37 eine Spalte zuvor gesetzt hat: Ein Teiljahr
 867    gehoert nicht in einen Jahresvergleich, und ``retired_source_codes`` ist
 868    einer. Der Preis ist bewusst getragen - ein echter neuer Code von 2026
 869    wird erst sichtbar, wenn 2026 voll ist.
 870
 871    **Die Differenz, kein Inventar.** Ein volles Codeinventar je Jahrgang
 872    waeren fuer Chicago rund 400 Codes mal sechs - kein Manifest, das jemand
 873    liest. Gefragt ist die **Aenderung**: neu und weggefallen. Das sind je
 874    Jahrgang eine Handvoll Zeilen.
 875
 876    Die Jahrgaenge kommen aus ``dim_date`` und nicht aus den Fakten: Ein
 877    Jahrgang mit Tagen, aber ohne Taten, ist eine Aussage und darf nicht
 878    fehlen. Er traegt ``offenses`` 0 und Anteile 0.0.
 879
 880    **Gemessen, nicht entschieden.** Das Publish-Gate bleibt global (siehe
 881    ``pruefe_gate``) - ein Bau soll nicht an einem Jahrgang scheitern, dessen
 882    Daten erst halb da sind. Ob ein Jahrgang die Schwellen haelt, haelt ein
 883    Test gegen dieses Manifest; dann scheitert die Suite und nicht der Bau.
 884    """
 885    def benannt(paare: set[tuple[str, str]]) -> list[dict[str, str]]:
 886        return [{"city": stadt, "code": code} for stadt, code in sorted(paare)]
 887
 888    zeilen = con.execute("""
 889        SELECT d.year, any_value(d.year_is_complete), f.reporting_city,
 890               f.source_offense_code, f.mapping_status, count(f.offense_id)
 891        FROM dim_date d LEFT JOIN fact_offense f ON f.date = d.date
 892        GROUP BY 1, 3, 4, 5
 893    """).fetchall()
 894
 895    gesamt: dict[int, int] = {}
 896    ganz: dict[int, bool] = {}
 897    je_status: dict[int, dict[str, int]] = {}
 898    offen: dict[int, list[tuple[str, str, int]]] = {}
 899    codes: dict[int, set[tuple[str, str]]] = {}
 900    for jahr, vollstaendig, stadt, code, status, n in zeilen:
 901        gesamt.setdefault(jahr, 0)
 902        ganz[jahr] = bool(vollstaendig)
 903        je_status.setdefault(jahr, {})
 904        offen.setdefault(jahr, [])
 905        codes.setdefault(jahr, set())
 906        # Ein Jahrgang ohne Taten kommt aus dem LEFT JOIN mit lauter NULL und
 907        # count 0. Er bekommt seinen Eintrag, aber nichts gezaehlt.
 908        if stadt is None:
 909            continue
 910        gesamt[jahr] += n
 911        je_status[jahr][status] = je_status[jahr].get(status, 0) + n
 912        # Ein Code, den die Quelle nicht mitliefert, laesst sich nicht beim
 913        # Namen nennen. Er zaehlt im Anteil mit und fehlt in den Listen - das
 914        # ist die ehrlichere von zwei Moeglichkeiten.
 915        if code is not None:
 916            codes[jahr].add((stadt, code))
 917            if status == "unmapped":
 918                offen[jahr].append((stadt, code, n))
 919
 920    ergebnis: dict[str, dict[str, Any]] = {}
 921    vorher: set[tuple[str, str]] | None = None
 922    for jahr in sorted(gesamt):
 923        n_gesamt = gesamt[jahr]
 924        eintrag: dict[str, Any] = {"offenses": n_gesamt}
 925        for wert in sorted(MAPPING_STATUS_WERTE):
 926            n = je_status[jahr].get(wert, 0)
 927            eintrag[wert] = round(100.0 * n / n_gesamt, 4) if n_gesamt else 0.0
 928        eintrag["unmapped_codes"] = [
 929            {"city": stadt, "code": code, "offenses": n}
 930            for stadt, code, n in sorted(offen[jahr],
 931                                         key=lambda z: (-z[2], z[0], z[1]))
 932        ]
 933        # Wer am Vergleich teilnimmt: nur ein **ganzer** Jahrgang mit Taten.
 934        #
 935        # Der aelteste hat keinen Vorgaenger - "alle Codes neu" waere dort
 936        # keine Aussage, sondern ein Inventar. Ein **Teiljahrgang** wird
 937        # gemeldet, aber nicht verglichen (siehe Docstring). Und ein Jahrgang
 938        # **ohne Taten** hat einen leeren Codesatz; stuende er im Vergleich,
 939        # waere dort jeder Code weggefallen und im naechsten wieder neu - eine
 940        # Bewegung, die es nie gab.
 941        #
 942        # In allen drei Faellen bleiben beide Listen leer, und ``vorher``
 943        # bleibt stehen: Verglichen wird gegen den letzten ganzen Jahrgang mit
 944        # Taten.
 945        vergleichbar = bool(n_gesamt and ganz[jahr])
 946        if vergleichbar and vorher is not None:
 947            eintrag["new_source_codes"] = benannt(codes[jahr] - vorher)
 948            eintrag["retired_source_codes"] = benannt(vorher - codes[jahr])
 949        else:
 950            eintrag["new_source_codes"] = []
 951            eintrag["retired_source_codes"] = []
 952        ergebnis[str(jahr)] = eintrag
 953        if vergleichbar:
 954            vorher = codes[jahr]
 955    return ergebnis

 958def pruefe_gate(anteile: dict[str, float],
 959                je_stadt: dict[str, dict[str, float]] | None = None) -> None:
 960    """Das Publish-Gate: Gold wird nur veroeffentlicht, wenn die Abdeckung traegt.
 961
 962    Gerufen wird es von ``build`` und nicht von ``reconcile`` - ein Nachweis
 963    misst, ein Gate entscheidet. Warum die Schwellen so weit unter den
 964    gemessenen Werten liegen, steht bei ``GATE_MINDESTENS``.
 965
 966    Geprueft wird der Gesamtanteil **und jede Stadt fuer sich**. Dieselben
 967    Schwellen: Wer den Vergleich zweier Staedte baut, muss ihn fuer beide
 968    tragen koennen. Ein Mittel ueber beide verdeckt sonst genau die Stadt, die
 969    bricht - siehe ``abdeckung_je_stadt``.
 970    """
 971    _gegen_schwellen(anteile, woher="insgesamt")
 972    for stadt, ihre in (je_stadt or {}).items():
 973        _gegen_schwellen(ihre, woher=stadt)
 974
 975
 976def _gegen_schwellen(anteile: dict[str, float], *, woher: str) -> None:
 977    for wert, boden in GATE_MINDESTENS.items():
 978        ist = anteile.get(wert, 0.0)
 979        if ist < boden:
 980            raise TransformError(
 981                f"Abdeckung reisst die Schwelle ({woher}): {wert} bei {ist} %, "
 982                f"verlangt sind mindestens {boden} %. Die Schwelle liegt weit "
 983                "unter dem gemessenen Stand - vor dem Hochsetzen pruefen, ob "
 984                "der raeumliche Join oder ein Crosswalk gebrochen ist."
 985            )
 986    for wert, decke in GATE_HOECHSTENS.items():
 987        ist = anteile.get(wert, 0.0)
 988        if ist > decke:
 989            raise TransformError(
 990                f"Abdeckung reisst die Schwelle ({woher}): {wert} bei {ist} %, "
 991                f"erlaubt sind hoechstens {decke} %."
 992            )

 995def reconcile(
 996    con: duckdb.DuckDBPyConnection, offense: Quelle, vintage: int
 997) -> dict[str, Any]:
 998    """Weist nach, dass Gold die Fakten vollstaendig traegt und die Schluessel passen.
 999
1000    Die Nachweise sind auf die Fehler zugeschnitten, die diese Schicht machen
1001    kann: eine Zeile beim Umschreiben verlieren, einen Fremdschluessel ins Leere
1002    zeigen lassen, oder jedem Tract zwei Staedte geben.
1003    """
1004    silber, zaehlend = con.execute(
1005        f"SELECT count(*), count(*) FILTER (WHERE counts) FROM {offense.relation}"
1006    ).fetchone()
1007    gold = con.execute("SELECT count(*) FROM fact_offense").fetchone()[0]
1008    if zaehlend != gold:
1009        raise TransformError(
1010            f"fact_offense hat {gold:,} Zeilen, in silver/crime_offense zaehlen "
1011            f"aber {zaehlend:,} von {silber:,}"
1012        )
1013    # Je Tat genau eine Zeile - sonst zaehlt Detroit doppelt, und das war der
1014    # Grund fuer diese Schicht.
1015    mehrfach = con.execute(
1016        "SELECT count(*) FROM (SELECT offense_group_id FROM fact_offense "
1017        "WHERE offense_group_id IS NOT NULL "
1018        "GROUP BY 1 HAVING count(*) > 1)"
1019    ).fetchone()[0]
1020    if mehrfach:
1021        raise TransformError(
1022            f"{mehrfach:,} Taten stehen mehrfach in fact_offense"
1023        )
1024
1025    verwaist_delikt = con.execute(
1026        "SELECT count(*) FROM fact_offense f "
1027        "LEFT JOIN dim_offense d ON d.nibrs_code = f.nibrs_code "
1028        "WHERE f.nibrs_code IS NOT NULL AND d.nibrs_code IS NULL"
1029    ).fetchone()[0]
1030    verwaist_tract = con.execute(
1031        "SELECT count(*) FROM fact_offense f "
1032        "LEFT JOIN dim_tract d ON d.geoid = f.tract_geoid "
1033        "WHERE f.tract_geoid IS NOT NULL AND d.geoid IS NULL"
1034    ).fetchone()[0]
1035    verwaist_tag = con.execute(
1036        "SELECT count(*) FROM fact_offense f "
1037        "LEFT JOIN dim_date d ON d.date = f.date WHERE d.date IS NULL"
1038    ).fetchone()[0]
1039    for name, anzahl in (
1040        ("dim_offense", verwaist_delikt),
1041        ("dim_tract", verwaist_tract),
1042        ("dim_date", verwaist_tag),
1043    ):
1044        if anzahl:
1045            raise TransformError(
1046                f"{anzahl:,} Zeilen in fact_offense zeigen auf keine Zeile in {name}"
1047            )
1048
1049    # Ein zurueckgezogener Code, der in den Daten vorkommt, muss sagen koennen,
1050    # was er heute bedeutet. Sonst laesst sich weder eine Zeitreihe ueber mehrere
1051    # Jahrgaenge lesen noch ein Filter bauen, der nichts verliert: Wer nach 26A
1052    # filtert, uebersieht sonst die Faelle, die frueher 90A hiessen.
1053    ungeloest = con.execute(
1054        "SELECT d.nibrs_code, count(*) FROM fact_offense f "
1055        "JOIN dim_offense d ON d.nibrs_code = f.nibrs_code "
1056        "WHERE d.retired AND d.resolution = 'unresolved' "
1057        "GROUP BY 1 ORDER BY 1"
1058    ).fetchall()
1059    if ungeloest:
1060        raise TransformError(
1061            "Zurueckgezogene Codes ohne Aufloesung in den Falldaten: "
1062            + ", ".join(f"{code} ({n:,} Faelle)" for code, n in ungeloest)
1063            + " - ZURUECKGEZOGEN in build_gold.py braucht einen belegten Eintrag"
1064        )
1065    ohne_begruendung = con.execute(
1066        "SELECT count(*) FROM dim_offense WHERE retired "
1067        "AND (retirement_note IS NULL OR trim(retirement_note) = '')"
1068    ).fetchone()[0]
1069    if ohne_begruendung:
1070        raise TransformError(
1071            f"{ohne_begruendung} zurueckgezogene Codes ohne Begruendung"
1072        )
1073
1074    mehrfach = con.execute(
1075        "SELECT count(*) FROM (SELECT geoid FROM dim_tract "
1076        "GROUP BY geoid HAVING count(*) > 1)"
1077    ).fetchone()[0]
1078    if mehrfach:
1079        raise TransformError(f"{mehrfach} Tracts stehen mehrfach in dim_tract")
1080
1081    # Die Einwohnerzahl steht seit Vertrag 6 in dim_tract_acs, je Vintage.
1082    # Genommen wird das Referenz-Vintage - dasselbe, aus dem die
1083    # Stadtzuordnung kommt, die hier nachgewiesen wird. Ein anderes Vintage
1084    # waere eine andere Zahl und kein Nachweis derselben Regel.
1085    einwohner = {
1086        zeile[0]: {"tracts": zeile[1], "population": zeile[2]}
1087        for zeile in con.execute(
1088            "SELECT d.city, count(*), sum(a.population) "
1089            "FROM dim_tract d JOIN dim_tract_acs a "
1090            "  ON a.geoid = d.geoid AND a.vintage = ? "
1091            "WHERE d.city IS NOT NULL GROUP BY d.city ORDER BY d.city",
1092            [vintage],
1093        ).fetchall()
1094    }
1095    fehlend = sorted(set(STADT_SCHLUESSEL.values()) - set(einwohner))
1096    if fehlend:
1097        raise TransformError(
1098            f"Keine Tracts der Stadt zugeordnet: {fehlend} - die Stadtgrenze "
1099            "aus silver/place passt nicht zu den Tracts"
1100        )
1101
1102    # Wo die meldende Stadt und die Stadt des Tracts auseinanderfallen, liegt
1103    # ein Fall knapp jenseits der Stadtgrenze. Das ist kein Fehler, aber es
1104    # gehoert gemessen - es ist der Preis der Mehrheitsregel.
1105    abweichend = con.execute(
1106        "SELECT count(*) FROM fact_offense f JOIN dim_tract d ON d.geoid = f.tract_geoid "
1107        "WHERE d.city IS NOT NULL AND d.city <> f.reporting_city"
1108    ).fetchone()[0]
1109    ausserhalb = con.execute(
1110        "SELECT count(*) FROM fact_offense f JOIN dim_tract d ON d.geoid = f.tract_geoid "
1111        "WHERE d.city IS NULL"
1112    ).fetchone()[0]
1113    verortet = con.execute(
1114        "SELECT count(*) FROM fact_offense WHERE tract_geoid IS NOT NULL"
1115    ).fetchone()[0]
1116
1117    zurueckgezogen = {
1118        zeile[0]: {
1119            "resolution": zeile[1],
1120            "replaced_by": zeile[2],
1121            "offenses": zeile[3],
1122        }
1123        for zeile in con.execute(
1124            "SELECT d.nibrs_code, d.resolution, d.replaced_by, count(f.offense_id) "
1125            "FROM dim_offense d LEFT JOIN fact_offense f ON f.nibrs_code = d.nibrs_code "
1126            "WHERE d.retired GROUP BY 1, 2, 3 ORDER BY 1"
1127        ).fetchall()
1128    }
1129
1130    anteile = abdeckung(con)
1131
1132    return {
1133        "verified": True,
1134        "grain": "eine Tat; Detroits weitere Anklagen bleiben in Silver",
1135        "coverage_percent": anteile,
1136        "coverage_percent_by_city": abdeckung_je_stadt(con),
1137        # FR-39: je Jahrgang, was abgedeckt ist. Beim Einjahresbau ist es ein
1138        # Eintrag - die Aussage ist dieselbe, nur kuerzer.
1139        "year_coverage": jahresabdeckung(con),
1140        # FR-38: dieselbe Frage fuer die Zuordnung, und mit den Codes beim
1141        # Namen. ``coverage_percent`` ist ein Mittel ueber alle Jahrgaenge und
1142        # verdeckt einen schlechten; ein unzugeordneter Code stand bis hierher
1143        # nur als Prozentsatz da, nie als Code.
1144        "mapping_by_year": zuordnung_je_jahrgang(con),
1145        "coverage_gate": {
1146            "minimum": GATE_MINDESTENS,
1147            "maximum": GATE_HOECHSTENS,
1148            "applies_to": "insgesamt und je meldender Stadt",
1149        },
1150        "fact_rows": gold,
1151        "silver_rows": silber,
1152        "silver_rows_counting": zaehlend,
1153        "charges_dropped": silber - zaehlend,
1154        "retired_codes": zurueckgezogen,
1155        "orphan_keys": {
1156            "dim_offense": verwaist_delikt,
1157            "dim_tract": verwaist_tract,
1158            "dim_date": verwaist_tag,
1159        },
1160        "tract_geoid_unique": True,
1161        "city_assignment": einwohner,
1162        "offenses_in_a_tract": verortet,
1163        "offenses_whose_tract_belongs_to_the_other_city": abweichend,
1164        "offenses_whose_tract_belongs_to_no_study_city": ausserhalb,
1165    }

1168def herkunft_der_quelle(q: Quelle) -> dict[str, Any]:
1169    """Wie Gold eine Quelle nennt - mit ihrem Stand, nicht nur ihrem Pfad.
1170
1171    Bis zum 14.9. stand hier ``{"layer", "table", "path"}``, und das war das
1172    schwaechste Glied der Herkunftskette: Ein Pfad zeigt auf das, was gerade
1173    dort liegt. Wird Silver neu gebaut, zeigt derselbe Satz auf etwas anderes
1174    - und nichts am Gold-Manifest verraet es. Jetzt steht dabei, **wann**
1175    jener Stand gebaut wurde, auf **welchen Eingaben** er ruhte, und
1176    woertlich dessen eigene Herkunft. Damit nennt ein Gold-Manifest die
1177    Bronze-Laeufe, aus denen seine Zahlen stammen, auch wenn Silver
1178    inzwischen weitergezogen ist.
1179
1180    Referenzdateien unter ``config/`` tragen stattdessen ihre Pruefsumme -
1181    sie werden aus amtlichen PDFs erzeugt und haben keinen Bauzeitpunkt.
1182    """
1183    kopf = {"layer": q.layer, "table": q.name}
1184    if q.layer == "config":
1185        return {**kopf, **referenzdatei(Path(q.pfad))}
1186    return {**kopf, **referenz(q.pfad, q.manifest or {})}

1220def build(data_root: Path, config_root: Path, vintage: int,
1221          vintages: tuple[int, ...] | None = None) -> dict[str, Path]:
1222    """Baut alle sechs Tabellen und veroeffentlicht sie einzeln atomar.
1223
1224    ``vintage`` ist das **Referenz**-Vintage: Aus ihm kommen Stadtzuordnung
1225    und Geometrie, und sie werden nicht je Jahrgang neu gerechnet.
1226
1227    ``vintages`` sind die ACS-Vintages, die als Nenner gebraucht werden - nicht
1228    die Jahrgaenge. Welcher Jahrgang welches Vintage leiht, entscheidet
1229    ``census_pipeline.vintage_for``, und das weiss der Gesamtlauf, der die
1230    Jahre kennt. Gold braucht davon nur die Spanne: Eine Tat traegt
1231    ``population_vintage`` und zeigt damit auf eine Zeile in ``dim_tract_acs``.
1232    Ohne Angabe ist es allein das Referenz-Vintage - dann baut dieser Lauf
1233    genau das, was er vor dem 3.10.2026 baute.
1234    """
1235    started = datetime.now(timezone.utc)
1236    vintages = tuple(sorted(set(vintages))) if vintages else (vintage,)
1237    offense = silver_quelle(data_root, "crime_offense")
1238    tract = silver_quelle(data_root, "tract", vintage)
1239    place = silver_quelle(data_root, "place", vintage)
1240    weather = silver_quelle(data_root, "weather_day")
1241    # Je Vintage eine eigene Quelle. Das Referenz-Vintage wird nicht zweimal
1242    # gelesen - ``silver_quelle`` liest das Manifest mit, und zwei Quellen auf
1243    # derselben Datei stuenden zweimal im Eingabe-Abdruck.
1244    acs_quellen = {
1245        v: (tract if v == vintage else silver_quelle(data_root, "tract", v))
1246        for v in vintages
1247    }
1248    for q in (offense, tract, place, weather):
1249        log.info("Quelle: silver/%s", q.name)
1250    log.info("Referenz-Vintage %d; ACS-Vintages %s", vintage,
1251             ", ".join(str(v) for v in vintages))
1252
1253    con = connect(spatial=True)
1254    ziele: dict[str, Path] = {}
1255    try:
1256        con.execute(
1257            f"CREATE TABLE dim_tract AS {dim_tract_query(tract, place, vintage)}"
1258        )
1259        con.execute(
1260            f"CREATE TABLE dim_tract_geo AS {dim_tract_geo_query(tract)}"
1261        )
1262        con.execute(
1263            f"CREATE TABLE dim_tract_acs AS {dim_tract_acs_query(acs_quellen)}"
1264        )
1265        con.execute(
1266            "CREATE TABLE dim_offense (nibrs_code VARCHAR, nibrs_description VARCHAR, "
1267            "nibrs_category VARCHAR, nibrs_family VARCHAR, nibrs_group VARCHAR, "
1268            "crime_against VARCHAR, federal_only BOOLEAN, retired BOOLEAN, "
1269            "replaced_by VARCHAR, resolution VARCHAR, retirement_note VARCHAR)"
1270        )
1271        con.executemany(
1272            "INSERT INTO dim_offense VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
1273            [tuple(z.values()) for z in dim_offense_rows(config_root)],
1274        )
1275        con.execute(f"CREATE TABLE dim_date AS {dim_date_query(offense)}")
1276        con.execute(
1277            f"CREATE TABLE dim_city_day AS {dim_city_day_query(weather, offense)}"
1278        )
1279        con.execute("CREATE TABLE fact_offense AS "
1280                    + fact_offense_query(offense, vintages=vintages))
1281
1282        nachweis = reconcile(con, offense, vintage)
1283        # Erst hier, nicht im Nachweis: Was gemessen wurde, steht im Manifest;
1284        # ob es reicht, entscheidet das Gate - und zwar bevor irgendeine
1285        # Tabelle veroeffentlicht wird.
1286        pruefe_gate(nachweis["coverage_percent"],
1287                    nachweis.get("coverage_percent_by_city"))
1288
1289        bauplan = [
1290            ("fact_offense", "eine Tat", [offense],
1291             {"granularitaet": (
1292                 "eine Zeile je Tat. Detroits Zeilen sind Anklagen - je Tat "
1293                 "zaehlt eine; Chicagos Zeile ist schon die Tat. Ohne das "
1294                 "waere Detroit um 3,8 Prozent zu hoch gezaehlt"),
1295              "alle_anklagen": (
1296                  "vollstaendig in silver/crime_offense, mit counts und "
1297                  "counts_reason je Zeile"),
1298              "reporting_city": "die meldende Stadt, nicht die Stadt des Tracts",
1299              "local_time_ambiguous": (
1300                  "die Ortszeit gab es zweimal - der Wechsel zurueck von der "
1301                  "Sommerzeit. Betrifft nur Chicago, das Wanduhrzeit ohne Zone "

271
272    Der Join ist ein innerer auf ``ST_Intersects`` und danach eine Fensterfunktion:
273    Ein Tract kann an beide Staedte grenzen - Chicago und Detroit liegen zwar
274    weit auseinander, aber die Regel darf davon nicht abhaengen. Genommen wird
275    der groesste Anteil, und nur wenn er ueber der Schwelle liegt.
276    """
277    staedte = ", ".join(
278        f"('{geoid}', '{schluessel}')"
279        for geoid, schluessel in sorted(STADT_SCHLUESSEL.items())
280    )
281    return f"""
282    WITH studienstadt(city_geoid, city) AS (VALUES {staedte}),
283    grenze AS (
284        SELECT s.city_geoid, s.city, ST_GeomFromWKB(p.geometry) AS geom
285        FROM {place.relation} p
286        JOIN studienstadt s ON s.city_geoid = p.geoid
287    ),
288    anteil AS (
289        SELECT
290            t.geoid,
291            g.city_geoid,
292            g.city,
293            ST_Area(ST_Intersection(ST_GeomFromWKB(t.geometry), g.geom))
294                / nullif(ST_Area(ST_GeomFromWKB(t.geometry)), 0) AS flaechenanteil
295        FROM {tract.relation} t
296        JOIN grenze g ON ST_Intersects(ST_GeomFromWKB(t.geometry), g.geom)
297    ),
298    beste AS (
299        SELECT * FROM (
300            SELECT *, row_number() OVER (
301                PARTITION BY geoid ORDER BY flaechenanteil DESC
302            ) AS rang
303            FROM anteil
304        ) WHERE rang = 1
305    )
306    SELECT
307        t.geoid                                         AS geoid,
308        CASE WHEN b.flaechenanteil > {STADT_SCHWELLE}
309             THEN b.city END                            AS city,
310        CASE WHEN b.flaechenanteil > {STADT_SCHWELLE}
311             THEN b.city_geoid END                      AS city_geoid,

313        -- rechnen will, braucht den Anteil, und wer die Regel pruefen will
314        -- auch. Ohne Beruehrung ist er 0 und nicht NULL.
315        coalesce(b.flaechenanteil, 0.0)                 AS city_area_share,
316        t.state_fips                                    AS state_fips,

318        t.county_fips                                   AS county_fips,

327        t.centroid_lat                                  AS centroid_lat,
328        t.centroid_lon                                  AS centroid_lon
329    FROM {tract.relation} t
