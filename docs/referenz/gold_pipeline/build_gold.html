gold_pipeline.build_gold

Baut die Gold-Schicht: eine Faktentabelle und vier Dimensionen.

Aufruf aus dem Projekt-Root:

python -m gold_pipeline.build_gold

Warum kein Wuerfel gebaut wird, steht in gold_pipeline/__init__.py. Hier steht, was statt dessen entsteht und woran es haengt.

Die Stadtzuordnung ist der eigentliche Grund fuer diese Schicht. Bis hierher konnte das Projekt keine Rate je Einwohner belegen: silver/tract deckt ganze Countys ab, und ein Tract sagt nicht, zu welcher Stadt er gehoert. dim_tract beantwortet das ueber die Ortsgrenzen aus silver/place.

Tracts liegen dabei nicht sauber in Stadtgrenzen, sondern ueberschreiten sie. Drei Regeln waeren denkbar, und sie fallen weit auseinander:

Regel                     Chicago      Detroit
alle beruehrten Tracts    3'080'550    884'691
Flaechengewichtung        2'651'921    638'570
Mehrheitsregel            2'661'953    638'635
Zensus 2020               2'746'388    639'111

Gewaehlt ist die Mehrheitsregel: Ein Tract gehoert zu der Stadt, die mehr als die Haelfte seiner Flaeche bedeckt. Sie gibt jedem Tract genau eine Stadt - die Voraussetzung dafuer, dass sich Faelle ohne Doppelzaehlung summieren lassen - und liegt praktisch gleichauf mit der Flaechengewichtung. Der verbleibende Abstand zum Zensus ist keine Ungenauigkeit der Regel, sondern der Unterschied zwischen einer ACS-Schaetzung und einer Zaehlung.

Gruppiert wird ueber die amtliche Kategorie, nicht ueber das Praefix. dim_offense fuehrt nibrs_category aus dem NIBRS User Manual 2025.0 - 28 Group-A-Kategorien und 10 fuer Group B, gelesen von tools/build_nibrs_categories.py. Die Deliktfamilie (nibrs_family) bleibt daneben als Kuerzel 13, 23, 26 ohne Bezeichnung stehen: Die Spezifikation fuehrt dafuer keine auslesbare Liste, und eine selbst geschriebene waere eine gepflegte Uebersetzung mehr. Sie ist seit den Kategorien aber auch kein Auswertungsweg mehr, sondern ein technisches Praefix

 159class Quelle(NamedTuple):
 160    """Etwas, aus dem eine Gold-Tabelle abgeleitet ist.
 161
 162    Meist eine Silver-Tabelle. ``dim_offense`` entsteht dagegen aus zwei
 163    versionierten CSV-Dateien unter ``config/`` - die Dimension traegt die
 164    ganze NIBRS-Klassifikation und muss sagen koennen, woher sie stammt.
 165    """
 166
 167    name: str
 168    pfad: str | Path   # Silver: lokal oder s3://; config: lokal
 169    layer: str = SILVER_LAYER
 170    # Das Manifest der Quelle, damit Gold ihren **Stand** nennen kann und
 171    # nicht nur ihren Pfad. Bei Referenzdateien unter config/ leer.
 172    manifest: dict[str, Any] | None = None
 173
 174    @property
 175    def relation(self) -> str:
 176        return f"read_parquet('{self.pfad}')"
 177
 178
 179def arguments() -> argparse.Namespace:
 180    parser = argparse.ArgumentParser(description=__doc__)
 181    parser.add_argument("--data-root", type=Path, default=None,
 182                        help="Wurzel der Schichten (Vorgabe: LOCAL_DATA_ROOT oder data)")
 183    parser.add_argument("--config-root", type=Path, default=Path("config"))
 184    parser.add_argument("--vintage", type=int, default=DEFAULT_VINTAGE)
 185    return parser.parse_args()

 202def silver_quelle(data_root: Path, name: str, vintage: int | None = None) -> Quelle:
 203    """Der Pfad einer Silver-Tabelle; mit Vintage, wo sie danach partitioniert ist.
 204
 205    Woher gelesen wird - lokal oder SeaweedFS - entscheidet die Ablage.
 206    """
 207    ablage = for_root(data_root)
 208    verzeichnis = f"{SILVER_LAYER}/dataset={name}"
 209    if vintage is not None:
 210        verzeichnis += f"/vintage={vintage}"
 211    if not ablage.exists(verzeichnis, PARQUET_FILE):
 212        treffer = ablage.list_files(verzeichnis, f"**/{PARQUET_FILE}")
 213        if not treffer:
 214            raise TransformError(
 215                f"Silver-Tabelle {name} fehlt unter {ablage.local_path(verzeichnis)}. "
 216                f"Zuerst bauen: python -m silver_pipeline.build_{name}"
 217            )
 218        verzeichnis = treffer[-1].rsplit("/", 1)[0]
 219    # Das Manifest wird mitgelesen: Gold soll sagen koennen, auf welchem
 220    # Silver-**Stand** es ruht - Zeitpunkt, Eingabe-Abdruck und dessen eigene
 221    # Herkunft. Ein Pfad allein zeigt nur auf das, was gerade dort liegt.
 222    manifest = {}
 223    if ablage.exists(verzeichnis, "manifest.json"):
 224        manifest = manifest_von(ablage, verzeichnis, "manifest.json")
 225    return Quelle(name, ablage.resolve_read_path(verzeichnis, PARQUET_FILE),
 226                  manifest=manifest)

 234def dim_tract_query(tract: Quelle, place: Quelle) -> str:
 235    """Ordnet jeden Tract der Stadt zu, die mehr als seine halbe Flaeche deckt.
 236
 237    Der Join ist ein innerer auf ``ST_Intersects`` und danach eine Fensterfunktion:
 238    Ein Tract kann an beide Staedte grenzen - Chicago und Detroit liegen zwar
 239    weit auseinander, aber die Regel darf davon nicht abhaengen. Genommen wird
 240    der groesste Anteil, und nur wenn er ueber der Schwelle liegt.
 241    """
 242    staedte = ", ".join(
 243        f"('{geoid}', '{schluessel}')"
 244        for geoid, schluessel in sorted(STADT_SCHLUESSEL.items())
 245    )
 246    return f"""
 247    WITH studienstadt(city_geoid, city) AS (VALUES {staedte}),
 248    grenze AS (
 249        SELECT s.city_geoid, s.city, ST_GeomFromWKB(p.geometry) AS geom
 250        FROM {place.relation} p
 251        JOIN studienstadt s ON s.city_geoid = p.geoid
 252    ),
 253    anteil AS (
 254        SELECT
 255            t.geoid,
 256            g.city_geoid,
 257            g.city,
 258            ST_Area(ST_Intersection(ST_GeomFromWKB(t.geometry), g.geom))
 259                / nullif(ST_Area(ST_GeomFromWKB(t.geometry)), 0) AS flaechenanteil
 260        FROM {tract.relation} t
 261        JOIN grenze g ON ST_Intersects(ST_GeomFromWKB(t.geometry), g.geom)
 262    ),
 263    beste AS (
 264        SELECT * FROM (
 265            SELECT *, row_number() OVER (
 266                PARTITION BY geoid ORDER BY flaechenanteil DESC
 267            ) AS rang
 268            FROM anteil
 269        ) WHERE rang = 1
 270    )
 271    SELECT
 272        t.geoid                                         AS geoid,
 273        CASE WHEN b.flaechenanteil > {STADT_SCHWELLE}
 274             THEN b.city END                            AS city,
 275        CASE WHEN b.flaechenanteil > {STADT_SCHWELLE}
 276             THEN b.city_geoid END                      AS city_geoid,
 277        -- Auch unterhalb der Schwelle festgehalten: Wer flaechengewichtet
 278        -- rechnen will, braucht den Anteil, und wer die Regel pruefen will
 279        -- auch. Ohne Beruehrung ist er 0 und nicht NULL.
 280        coalesce(b.flaechenanteil, 0.0)                 AS city_area_share,
 281        t.state_fips                                    AS state_fips,
 282        t.state_name                                    AS state_name,
 283        t.county_fips                                   AS county_fips,
 284        t.name                                          AS tract_name,
 285        t.population                                    AS population,
 286        t.median_household_income_usd                   AS median_household_income_usd,
 287        t.poverty_rate                                  AS poverty_rate,
 288        t.land_area_m2                                  AS land_area_m2,
 289        t.centroid_lat                                  AS centroid_lat,
 290        t.centroid_lon                                  AS centroid_lon
 291    FROM {tract.relation} t
 292    LEFT JOIN beste b ON b.geoid = t.geoid
 293    ORDER BY geoid
 294    """

 302def dim_offense_rows(config_root: Path) -> list[dict[str, Any]]:
 303    """Die amtliche NIBRS-Codeliste, plus die Codes, die nur noch die Daten kennen.
 304
 305    Vier NIBRS-Codes hat das FBI zurueckgezogen; die MICR-Quellen von 2009 und
 306    2024 fuehren sie weiter, und zwei davon stehen in den Falldaten 2024 -
 307    ``90I Runaway`` mit 969 und ``90A Bad Checks`` mit 50 Faellen. Stuenden sie
 308    nicht in dieser Dimension, wuerde jede Auswertung, die ueber sie filtert,
 309    1'019 Delikte stillschweigend verlieren. Genau diese Art von Verlust soll
 310    ein Sternschema verhindern und nicht verursachen.
 311
 312    Sie werden deshalb aufgenommen und als ``retired`` gekennzeichnet. Ihre
 313    Bezeichnung stammt aus den Crosswalks, die sie noch fuehren - nicht aus der
 314    Spezifikation, die sie nicht mehr kennt.
 315    """
 316    pfad = config_root / NIBRS_CODES
 317    if not pfad.exists():
 318        raise TransformError(f"Codeliste fehlt: {pfad}")
 319    with pfad.open(encoding="utf-8") as datei:
 320        amtlich = list(csv.DictReader(datei))
 321    if not amtlich:
 322        raise TransformError(f"Codeliste ist leer: {pfad}")
 323
 324    kat_pfad = config_root / NIBRS_KATEGORIEN
 325    if not kat_pfad.exists():
 326        raise TransformError(
 327            f"Kategorienliste fehlt: {kat_pfad}. "
 328            "Zuerst: python tools/build_nibrs_categories.py"
 329        )
 330    with kat_pfad.open(encoding="utf-8") as datei:
 331        kategorie = {z["nibrs_code"]: z["nibrs_category"] for z in csv.DictReader(datei)}
 332
 333    ohne_kategorie = sorted(
 334        z["nibrs_code"] for z in amtlich if z["nibrs_code"] not in kategorie
 335    )
 336    if ohne_kategorie:
 337        raise TransformError(
 338            f"Codes ohne Kategorie: {ohne_kategorie} - "
 339            "tools/build_nibrs_categories.py neu laufen lassen"
 340        )
 341
 342    zeilen = []
 343    for z in amtlich:
 344        code = z["nibrs_code"]
 345        ersatz, aufloesung, grund = UMGESCHLUESSELT.get(code, (None, "current", None))
 346        zeilen.append({
 347            "nibrs_code": code,
 348            "nibrs_description": z["nibrs_description"],
 349            "nibrs_category": kategorie[code],
 350            "nibrs_family": code[:2],
 351            "nibrs_group": z["nibrs_group"],
 352            "crime_against": z["crime_against"],
 353            "federal_only": z["federal_only"] == "true",
 354            "retired": False,
 355            "replaced_by": ersatz,
 356            "resolution": aufloesung,
 357            "retirement_note": grund,
 358        })
 359
 360    bekannt = {z["nibrs_code"] for z in zeilen}
 361    for name in CROSSWALKS:
 362        quelle = config_root / name
 363        if not quelle.exists():
 364            continue
 365        with quelle.open(encoding="utf-8") as datei:
 366            for z in csv.DictReader(datei):
 367                code = (z.get("nibrs_code") or z.get("ibr_code") or "").strip()
 368                if not code or code in bekannt:
 369                    continue
 370                bekannt.add(code)
 371                ersatz, aufloesung, grund = ZURUECKGEZOGEN.get(
 372                    code, (None, "unresolved", "kein Beleg hinterlegt")
 373                )
 374                zeilen.append({
 375                    "nibrs_code": code,
 376                    "nibrs_description": (
 377                        z.get("nibrs_description") or z.get("ibr_category") or ""
 378                    ).strip(),
 379                    "nibrs_category": kategorie.get(code, ""),
 380                    "nibrs_family": code[:2],
 381                    "nibrs_group": (z.get("nibrs_group") or "B").strip() or "B",
 382                    "crime_against": "",
 383                    "federal_only": False,
 384                    "retired": True,
 385                    "replaced_by": ersatz,
 386                    "resolution": aufloesung,
 387                    "retirement_note": grund,
 388                })
 389    return sorted(zeilen, key=lambda z: z["nibrs_code"])

 392def dim_date_query(offense: Quelle) -> str:
 393    """Ein Kalendertag je Zeile, ueber die Spanne der Falldaten.
 394
 395    Erzeugt wird die Reihe und nicht aus den Fakten abgeleitet: Ein Tag ohne
 396    Delikt ist eine Aussage und darf nicht fehlen, sonst zeigt eine Zeitreihe
 397    eine Luecke als Nicht-Ereignis.
 398    """
 399    return f"""
 400    WITH spanne AS (
 401        SELECT min(occurred_date_local) AS von, max(occurred_date_local) AS bis
 402        FROM {offense.relation}
 403    )
 404    -- generate_series liefert auf DATE-Grenzen TIMESTAMP zurueck. Ohne den
 405    -- Cast traegt die Dimension einen anderen Typ als der Schluessel in
 406    -- fact_offense, und der Join haengt an einer stillschweigenden Umwandlung.
 407    SELECT
 408        CAST(tag AS DATE)                               AS date,
 409        -- Schmale Typen, weil die Sache schmal ist: ein Jahr passt in
 410        -- SMALLINT, alles Uebrige in TINYINT (-128 bis 127). DuckDBs
 411        -- Datumsfunktionen liefern durchweg BIGINT; ohne CAST stuende in
 412        -- einer Dimensionstabelle achtmal so viel Platz wie noetig.
 413        CAST(year(tag) AS SMALLINT)                     AS year,
 414        CAST(month(tag) AS TINYINT)                     AS month,
 415        CAST(quarter(tag) AS TINYINT)                   AS quarter,
 416        CAST(day(tag) AS TINYINT)                       AS day_of_month,
 417        CAST(dayofweek(tag) AS TINYINT)                 AS day_of_week,
 418        dayname(tag)                                    AS day_name,
 419        monthname(tag)                                  AS month_name,
 420        CAST(date_trunc('month', tag) AS DATE)          AS month_start,
 421        dayofweek(tag) IN (0, 6)                        AS is_weekend,
 422        CAST(dayofyear(tag) AS SMALLINT)                AS day_of_year
 423    FROM spanne, unnest(generate_series(von, bis, INTERVAL 1 DAY)) AS t(tag)
 424    ORDER BY date
 425    """

 434
 435    **Warum die beiden Spurenspalten mitkommen.** NOAA kennt ein Messflag
 436    ``T``: gefallen, aber unter der Aufloesung des Geraets. Der Messwert ist
 437    dann ``0``, und das heisst etwas anderes als *trocken*. Silver haelt den
 438    Unterschied seit jeher in ``precipitation_trace`` und ``snowfall_trace``;
 439    Gold liess beide Spalten bis zum 15.9.2026 fallen.
 440
 441    Gemessen war das keine Feinheit: Von den 481 Gold-Tagen mit ``0`` mm
 442    Niederschlag sind **113 Spurentage** - 45 in Chicago, 68 in Detroit. Eine
 443    Abfrage nach trockenen Tagen zaehlte sie mit, und niemand konnte es der
 444    Tabelle ansehen. Konzept 9.3 verlangt ausdruecklich, dass die
 445    Spurenmengen in Gold erhalten bleiben.
 446    """
 447    return f"""
 448    WITH spanne AS (
 449        SELECT min(occurred_date_local) AS von, max(occurred_date_local) AS bis
 450        FROM {offense.relation}
 451    )
 452    SELECT
 453        w.city                                          AS city,
 454        w.date                                          AS date,
 455        w.station_id                                    AS station_id,
 456        w.station_name                                  AS station_name,
 457        w.temp_max_c                                    AS temp_max_c,
 458        w.temp_min_c                                    AS temp_min_c,
 459        w.precipitation_mm                              AS precipitation_mm,
 460        w.snowfall_mm                                   AS snowfall_mm,
 461        w.precipitation_trace                           AS precipitation_trace,
 462        w.snowfall_trace                                AS snowfall_trace,
 463        w.quality_flags                                 AS quality_flags
 464    FROM {weather.relation} w, spanne
 465    WHERE w.date BETWEEN spanne.von AND spanne.bis
 466    ORDER BY city, date
 467    """

 475def fact_offense_query(offense: Quelle, tracts: str = "dim_tract") -> str:
 476    """Eine Zeile je **Tat**, mit den Schluesseln der Dimensionen.
 477
 478    Hier liegt der einzige Stellenwechsel gegenueber Silver. Detroits Zeilen
 479    sind **Anklagen**, Chicagos sind **Delikte**: Ein Ueberfall mit Schuessen
 480    und geraubtem Auto steht bei Detroit als fuenf Zeilen, bei Chicago als
 481    eine. Wer beide summiert, zaehlt Detroit um 3,8 Prozent zu hoch.
 482
 483    Silver haelt deshalb jede Anklage und markiert je Tat eine Zeile mit
 484    ``counts``; Gold nimmt nur diese. Wer die Anklagen braucht - "wie oft wurde
 485    zusaetzlich Sachbeschaedigung angezeigt" -, findet sie vollstaendig in
 486    ``silver/crime_offense``.
 487
 488    Dazu kommt ``counts_case`` unveraendert aus Silver: je **Fall** eine Zeile,
 489    die mit dem schwersten Delikt. Chicago fuehrt je Vorfall ein Delikt,
 490    Detroit jedes - auf Tatebene zaehlt Detroit 6,4 Prozent, die Chicago nie
 491    zaehlt. Wer beide Staedte auf Chicagos Zaehlweise vergleichen will, filtert
 492    auf ``counts_case``; die Tatzahlen bleiben, wie sie sind.
 493
 494
 495    Ergaenzt werden nur Groessen, die sich aus dem Zeitstempel ableiten, und die
 496    Deliktfamilie. Sie sparen keine Laufzeit - gemessen 0,3 Millisekunden -,
 497    sondern ersparen jeder Abfrage das Wissen, dass die Familie die ersten
 498    beiden Zeichen des Codes sind.
 499    """
 500    return f"""
 501    SELECT
 502        o.offense_id                                    AS offense_id,
 503        o.event_id                                      AS event_id,
 504        o.city                                          AS reporting_city,
 505        o.occurred_at_utc                               AS occurred_at_utc,
 506        o.occurred_at_local                             AS occurred_at_local,
 507        o.occurred_date_local                           AS date,
 508        CAST(hour(o.occurred_at_local) AS TINYINT)      AS hour_of_day,
 509        -- Genau hier wird die Spalte gebraucht: Eine Stundenverteilung ueber
 510        -- hour_of_day zaehlt eine mehrdeutige Ortszeit in einen der beiden
 511        -- Toepfe, und ohne diese Spalte ist nicht zu sehen, welche Zeilen das
 512        -- betrifft. Chicago liefert Wanduhrzeit ohne Zone; 48 Zeilen liegen in
 513        -- der Stunde, die es am 3.11.2024 zweimal gab.
 514        o.local_time_ambiguous                          AS local_time_ambiguous,
 515        o.tract_geoid                                   AS tract_geoid,
 516        o.nibrs_code                                    AS nibrs_code,
 517        left(o.nibrs_code, 2)                           AS nibrs_family,
 518        o.source_offense_code                           AS source_offense_code,
 519        o.source_offense_description                    AS source_offense_description,
 520        o.latitude                                      AS latitude,
 521        o.longitude                                     AS longitude,
 522        o.located                                       AS located,
 523        o.mapping_status                                AS mapping_status,
 524        -- Warum eine Zeile in einer Tract-Auswertung fehlt, in einem Wort.
 525        -- ``located`` sagt nur ja oder nein; hier steht der Grund, und die
 526        -- vierte Stufe braucht die Stadtgrenze - deshalb entsteht die Spalte
 527        -- in Gold und nicht in Silver.
 528        CASE
 529            WHEN o.latitude IS NULL   THEN 'missing_coordinate'
 530            WHEN o.tract_geoid IS NULL THEN 'no_tract'
 531            WHEN t.city IS NULL        THEN 'outside_city'
 532            ELSE 'inside_city'
 533        END                                             AS geo_status,
 534        o.arrest                                        AS arrest,
 535        o.unfounded                                     AS unfounded,
 536        o.offense_group_id                              AS offense_group_id,
 537        o.counts_case                                   AS counts_case
 538    FROM {offense.relation} o
 539    LEFT JOIN {tracts} t ON t.geoid = o.tract_geoid
 540    WHERE o.counts
 541    """

 549def abdeckung(con: duckdb.DuckDBPyConnection) -> dict[str, float]:
 550    """Misst, wie sich die Fakten auf die beiden Statusspalten verteilen.
 551
 552    Nur messen - ob die Anteile ausreichen, entscheidet ``pruefe_gate``. Die
 553    Trennung ist Absicht: Eine Messung darf auch dann Zahlen liefern, wenn sie
 554    schlecht aussehen, und eine Testfixture mit zwei Zeilen hat naturgemaess
 555    schraege Anteile.
 556
 557    Eine Pruefung steckt trotzdem hier, weil sie keine Ermessensfrage ist:
 558    Kommt in ``mapping_status`` oder ``geo_status`` ein Wert vor, den der Code
 559    nicht kennt, hat jemand die Einstufung geaendert - dann bleibt der Bau
 560    stehen, statt eine Kennzahl still zu verschieben.
 561    """
 562    unbekannt = {}
 563    for spalte, erlaubt in (("mapping_status", MAPPING_STATUS_WERTE),
 564                            ("geo_status", GEO_STATUS_WERTE)):
 565        fremd = sorted(
 566            str(z[0]) for z in con.execute(
 567                f"SELECT DISTINCT {spalte} FROM fact_offense"
 568            ).fetchall() if z[0] not in erlaubt
 569        )
 570        if fremd:
 571            unbekannt[spalte] = fremd
 572    if unbekannt:
 573        raise TransformError(
 574            f"Unbekannte Statuswerte in fact_offense: {unbekannt}. Entweder "
 575            "ist die Einstufung geaendert worden - dann gehoert der neue Wert "
 576            "in MAPPING_STATUS_WERTE beziehungsweise GEO_STATUS_WERTE - oder "
 577            "es ist ein Tippfehler."
 578        )
 579
 580    gesamt = con.execute("SELECT count(*) FROM fact_offense").fetchone()[0]
 581    anteile: dict[str, float] = {}
 582    for spalte, werte in (("geo_status", GEO_STATUS_WERTE),
 583                          ("mapping_status", MAPPING_STATUS_WERTE)):
 584        for wert in sorted(werte):
 585            n = con.execute(
 586                f"SELECT count(*) FROM fact_offense WHERE {spalte} = ?", [wert]
 587            ).fetchone()[0]
 588            anteile[wert] = round(100.0 * n / gesamt, 4) if gesamt else 0.0
 589
 590    return anteile

 593def abdeckung_je_stadt(con: duckdb.DuckDBPyConnection) -> dict[str, dict[str, float]]:
 594    """Dieselben Anteile, aber je meldender Stadt.
 595
 596    **Warum das noetig ist.** Der Gesamtanteil ist ein Mittel, und ein Mittel
 597    verdeckt. Eine externe Pruefung hat das am 15.9.2026 vorgerechnet: 750
 598    Chicagoer Zeilen zu 100 % exakt und 250 Detroiter zu 70 % ergeben 92,5 %
 599    gemeinsam - bestanden, bei einer Schwelle von 85 %. Detroits Crosswalk
 600    haette also zu einem Drittel brechen koennen, ohne dass etwas rot wird.
 601
 602    Chicago ist dreimal so gross wie Detroit. Genau deshalb traegt der
 603    Gesamtanteil Chicagos Zahl und nicht Detroits.
 604    """
 605    zeilen = con.execute("""
 606        SELECT reporting_city, geo_status, mapping_status, count(*)
 607        FROM fact_offense GROUP BY 1, 2, 3
 608    """).fetchall()
 609    gesamt: dict[str, int] = {}
 610    treffer: dict[str, dict[str, int]] = {}
 611    for stadt, geo, mapping, n in zeilen:
 612        gesamt[stadt] = gesamt.get(stadt, 0) + n
 613        je = treffer.setdefault(stadt, {})
 614        for wert in (geo, mapping):
 615            je[wert] = je.get(wert, 0) + n
 616
 617    ergebnis: dict[str, dict[str, float]] = {}
 618    for stadt, n_gesamt in sorted(gesamt.items()):
 619        je = treffer.get(stadt, {})
 620        ergebnis[stadt] = {
 621            wert: round(100.0 * je.get(wert, 0) / n_gesamt, 4) if n_gesamt else 0.0
 622            for wert in sorted(set(GEO_STATUS_WERTE) | set(MAPPING_STATUS_WERTE))
 623        }
 624    return ergebnis

 627def pruefe_gate(anteile: dict[str, float],
 628                je_stadt: dict[str, dict[str, float]] | None = None) -> None:
 629    """Das Publish-Gate: Gold wird nur veroeffentlicht, wenn die Abdeckung traegt.
 630
 631    Gerufen wird es von ``build`` und nicht von ``reconcile`` - ein Nachweis
 632    misst, ein Gate entscheidet. Warum die Schwellen so weit unter den
 633    gemessenen Werten liegen, steht bei ``GATE_MINDESTENS``.
 634
 635    Geprueft wird der Gesamtanteil **und jede Stadt fuer sich**. Dieselben
 636    Schwellen: Wer den Vergleich zweier Staedte baut, muss ihn fuer beide
 637    tragen koennen. Ein Mittel ueber beide verdeckt sonst genau die Stadt, die
 638    bricht - siehe ``abdeckung_je_stadt``.
 639    """
 640    _gegen_schwellen(anteile, woher="insgesamt")
 641    for stadt, ihre in (je_stadt or {}).items():
 642        _gegen_schwellen(ihre, woher=stadt)
 643
 644
 645def _gegen_schwellen(anteile: dict[str, float], *, woher: str) -> None:
 646    for wert, boden in GATE_MINDESTENS.items():
 647        ist = anteile.get(wert, 0.0)
 648        if ist < boden:
 649            raise TransformError(
 650                f"Abdeckung reisst die Schwelle ({woher}): {wert} bei {ist} %, "
 651                f"verlangt sind mindestens {boden} %. Die Schwelle liegt weit "
 652                "unter dem gemessenen Stand - vor dem Hochsetzen pruefen, ob "
 653                "der raeumliche Join oder ein Crosswalk gebrochen ist."
 654            )
 655    for wert, decke in GATE_HOECHSTENS.items():
 656        ist = anteile.get(wert, 0.0)
 657        if ist > decke:
 658            raise TransformError(
 659                f"Abdeckung reisst die Schwelle ({woher}): {wert} bei {ist} %, "
 660                f"erlaubt sind hoechstens {decke} %."
 661            )

 664def reconcile(
 665    con: duckdb.DuckDBPyConnection, offense: Quelle
 666) -> dict[str, Any]:
 667    """Weist nach, dass Gold die Fakten vollstaendig traegt und die Schluessel passen.
 668
 669    Die Nachweise sind auf die Fehler zugeschnitten, die diese Schicht machen
 670    kann: eine Zeile beim Umschreiben verlieren, einen Fremdschluessel ins Leere
 671    zeigen lassen, oder jedem Tract zwei Staedte geben.
 672    """
 673    silber, zaehlend = con.execute(
 674        f"SELECT count(*), count(*) FILTER (WHERE counts) FROM {offense.relation}"
 675    ).fetchone()
 676    gold = con.execute("SELECT count(*) FROM fact_offense").fetchone()[0]
 677    if zaehlend != gold:
 678        raise TransformError(
 679            f"fact_offense hat {gold:,} Zeilen, in silver/crime_offense zaehlen "
 680            f"aber {zaehlend:,} von {silber:,}"
 681        )
 682    # Je Tat genau eine Zeile - sonst zaehlt Detroit doppelt, und das war der
 683    # Grund fuer diese Schicht.
 684    mehrfach = con.execute(
 685        "SELECT count(*) FROM (SELECT offense_group_id FROM fact_offense "
 686        "WHERE offense_group_id IS NOT NULL "
 687        "GROUP BY 1 HAVING count(*) > 1)"
 688    ).fetchone()[0]
 689    if mehrfach:
 690        raise TransformError(
 691            f"{mehrfach:,} Taten stehen mehrfach in fact_offense"
 692        )
 693
 694    verwaist_delikt = con.execute(
 695        "SELECT count(*) FROM fact_offense f "
 696        "LEFT JOIN dim_offense d ON d.nibrs_code = f.nibrs_code "
 697        "WHERE f.nibrs_code IS NOT NULL AND d.nibrs_code IS NULL"
 698    ).fetchone()[0]
 699    verwaist_tract = con.execute(
 700        "SELECT count(*) FROM fact_offense f "
 701        "LEFT JOIN dim_tract d ON d.geoid = f.tract_geoid "
 702        "WHERE f.tract_geoid IS NOT NULL AND d.geoid IS NULL"
 703    ).fetchone()[0]
 704    verwaist_tag = con.execute(
 705        "SELECT count(*) FROM fact_offense f "
 706        "LEFT JOIN dim_date d ON d.date = f.date WHERE d.date IS NULL"
 707    ).fetchone()[0]
 708    for name, anzahl in (
 709        ("dim_offense", verwaist_delikt),
 710        ("dim_tract", verwaist_tract),
 711        ("dim_date", verwaist_tag),
 712    ):
 713        if anzahl:
 714            raise TransformError(
 715                f"{anzahl:,} Zeilen in fact_offense zeigen auf keine Zeile in {name}"
 716            )
 717
 718    # Ein zurueckgezogener Code, der in den Daten vorkommt, muss sagen koennen,
 719    # was er heute bedeutet. Sonst laesst sich weder eine Zeitreihe ueber mehrere
 720    # Jahrgaenge lesen noch ein Filter bauen, der nichts verliert: Wer nach 26A
 721    # filtert, uebersieht sonst die Faelle, die frueher 90A hiessen.
 722    ungeloest = con.execute(
 723        "SELECT d.nibrs_code, count(*) FROM fact_offense f "
 724        "JOIN dim_offense d ON d.nibrs_code = f.nibrs_code "
 725        "WHERE d.retired AND d.resolution = 'unresolved' "
 726        "GROUP BY 1 ORDER BY 1"
 727    ).fetchall()
 728    if ungeloest:
 729        raise TransformError(
 730            "Zurueckgezogene Codes ohne Aufloesung in den Falldaten: "
 731            + ", ".join(f"{code} ({n:,} Faelle)" for code, n in ungeloest)
 732            + " - ZURUECKGEZOGEN in build_gold.py braucht einen belegten Eintrag"
 733        )
 734    ohne_begruendung = con.execute(
 735        "SELECT count(*) FROM dim_offense WHERE retired "
 736        "AND (retirement_note IS NULL OR trim(retirement_note) = '')"
 737    ).fetchone()[0]
 738    if ohne_begruendung:
 739        raise TransformError(
 740            f"{ohne_begruendung} zurueckgezogene Codes ohne Begruendung"
 741        )
 742
 743    mehrfach = con.execute(
 744        "SELECT count(*) FROM (SELECT geoid FROM dim_tract "
 745        "GROUP BY geoid HAVING count(*) > 1)"
 746    ).fetchone()[0]
 747    if mehrfach:
 748        raise TransformError(f"{mehrfach} Tracts stehen mehrfach in dim_tract")
 749
 750    einwohner = {
 751        zeile[0]: {"tracts": zeile[1], "population": zeile[2]}
 752        for zeile in con.execute(
 753            "SELECT city, count(*), sum(population) FROM dim_tract "
 754            "WHERE city IS NOT NULL GROUP BY city ORDER BY city"
 755        ).fetchall()
 756    }
 757    fehlend = sorted(set(STADT_SCHLUESSEL.values()) - set(einwohner))
 758    if fehlend:
 759        raise TransformError(
 760            f"Keine Tracts der Stadt zugeordnet: {fehlend} - die Stadtgrenze "
 761            "aus silver/place passt nicht zu den Tracts"
 762        )
 763
 764    # Wo die meldende Stadt und die Stadt des Tracts auseinanderfallen, liegt
 765    # ein Fall knapp jenseits der Stadtgrenze. Das ist kein Fehler, aber es
 766    # gehoert gemessen - es ist der Preis der Mehrheitsregel.
 767    abweichend = con.execute(
 768        "SELECT count(*) FROM fact_offense f JOIN dim_tract d ON d.geoid = f.tract_geoid "
 769        "WHERE d.city IS NOT NULL AND d.city <> f.reporting_city"
 770    ).fetchone()[0]
 771    ausserhalb = con.execute(
 772        "SELECT count(*) FROM fact_offense f JOIN dim_tract d ON d.geoid = f.tract_geoid "
 773        "WHERE d.city IS NULL"
 774    ).fetchone()[0]
 775    verortet = con.execute(
 776        "SELECT count(*) FROM fact_offense WHERE tract_geoid IS NOT NULL"
 777    ).fetchone()[0]
 778
 779    zurueckgezogen = {
 780        zeile[0]: {
 781            "resolution": zeile[1],
 782            "replaced_by": zeile[2],
 783            "offenses": zeile[3],
 784        }
 785        for zeile in con.execute(
 786            "SELECT d.nibrs_code, d.resolution, d.replaced_by, count(f.offense_id) "
 787            "FROM dim_offense d LEFT JOIN fact_offense f ON f.nibrs_code = d.nibrs_code "
 788            "WHERE d.retired GROUP BY 1, 2, 3 ORDER BY 1"
 789        ).fetchall()
 790    }
 791
 792    anteile = abdeckung(con)
 793
 794    return {
 795        "verified": True,
 796        "grain": "eine Tat; Detroits weitere Anklagen bleiben in Silver",
 797        "coverage_percent": anteile,
 798        "coverage_percent_by_city": abdeckung_je_stadt(con),
 799        "coverage_gate": {
 800            "minimum": GATE_MINDESTENS,
 801            "maximum": GATE_HOECHSTENS,
 802            "applies_to": "insgesamt und je meldender Stadt",
 803        },
 804        "fact_rows": gold,
 805        "silver_rows": silber,
 806        "silver_rows_counting": zaehlend,
 807        "charges_dropped": silber - zaehlend,
 808        "retired_codes": zurueckgezogen,
 809        "orphan_keys": {
 810            "dim_offense": verwaist_delikt,
 811            "dim_tract": verwaist_tract,
 812            "dim_date": verwaist_tag,
 813        },
 814        "tract_geoid_unique": True,
 815        "city_assignment": einwohner,
 816        "offenses_in_a_tract": verortet,
 817        "offenses_whose_tract_belongs_to_the_other_city": abweichend,
 818        "offenses_whose_tract_belongs_to_no_study_city": ausserhalb,
 819    }

 822def herkunft_der_quelle(q: Quelle) -> dict[str, Any]:
 823    """Wie Gold eine Quelle nennt - mit ihrem Stand, nicht nur ihrem Pfad.
 824
 825    Bis zum 14.9. stand hier ``{"layer", "table", "path"}``, und das war das
 826    schwaechste Glied der Herkunftskette: Ein Pfad zeigt auf das, was gerade
 827    dort liegt. Wird Silver neu gebaut, zeigt derselbe Satz auf etwas anderes
 828    - und nichts am Gold-Manifest verraet es. Jetzt steht dabei, **wann**
 829    jener Stand gebaut wurde, auf **welchen Eingaben** er ruhte, und
 830    woertlich dessen eigene Herkunft. Damit nennt ein Gold-Manifest die
 831    Bronze-Laeufe, aus denen seine Zahlen stammen, auch wenn Silver
 832    inzwischen weitergezogen ist.
 833
 834    Referenzdateien unter ``config/`` tragen stattdessen ihre Pruefsumme -
 835    sie werden aus amtlichen PDFs erzeugt und haben keinen Bauzeitpunkt.
 836    """
 837    kopf = {"layer": q.layer, "table": q.name}
 838    if q.layer == "config":
 839        return {**kopf, **referenzdatei(Path(q.pfad))}
 840    return {**kopf, **referenz(q.pfad, q.manifest or {})}

 874def build(data_root: Path, config_root: Path, vintage: int) -> dict[str, Path]:
 875    """Baut alle fuenf Tabellen und veroeffentlicht sie einzeln atomar."""
 876    started = datetime.now(timezone.utc)
 877    offense = silver_quelle(data_root, "crime_offense")
 878    tract = silver_quelle(data_root, "tract", vintage)
 879    place = silver_quelle(data_root, "place", vintage)
 880    weather = silver_quelle(data_root, "weather_day")
 881    for q in (offense, tract, place, weather):
 882        log.info("Quelle: silver/%s", q.name)
 883
 884    con = connect(spatial=True)
 885    ziele: dict[str, Path] = {}
 886    try:
 887        con.execute(f"CREATE TABLE dim_tract AS {dim_tract_query(tract, place)}")
 888        con.execute(
 889            "CREATE TABLE dim_offense (nibrs_code VARCHAR, nibrs_description VARCHAR, "
 890            "nibrs_category VARCHAR, nibrs_family VARCHAR, nibrs_group VARCHAR, "
 891            "crime_against VARCHAR, federal_only BOOLEAN, retired BOOLEAN, "
 892            "replaced_by VARCHAR, resolution VARCHAR, retirement_note VARCHAR)"
 893        )
 894        con.executemany(
 895            "INSERT INTO dim_offense VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
 896            [tuple(z.values()) for z in dim_offense_rows(config_root)],
 897        )
 898        con.execute(f"CREATE TABLE dim_date AS {dim_date_query(offense)}")
 899        con.execute(
 900            f"CREATE TABLE dim_city_day AS {dim_city_day_query(weather, offense)}"
 901        )
 902        con.execute(f"CREATE TABLE fact_offense AS {fact_offense_query(offense)}")
 903
 904        nachweis = reconcile(con, offense)
 905        # Erst hier, nicht im Nachweis: Was gemessen wurde, steht im Manifest;
 906        # ob es reicht, entscheidet das Gate - und zwar bevor irgendeine
 907        # Tabelle veroeffentlicht wird.

  • und nichts am Gold-Manifest verraet es. Jetzt steht dabei, wann jener Stand gebaut wurde, auf welchen Eingaben er ruhte, und woertlich dessen eigene Herkunft. Damit nennt ein Gold-Manifest die Bronze-Laeufe, aus denen seine Zahlen stammen, auch wenn Silver inzwischen weitergezogen ist.

Referenzdateien unter config/ tragen stattdessen ihre Pruefsumme - sie werden aus amtlichen PDFs erzeugt und haben keinen Bauzeitpunkt.
