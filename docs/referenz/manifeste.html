manifeste

Ein Leser fuer die Manifeste - statt elf.

Jede Schicht schreibt je Lauf oder Tabelle ein manifest.json. Es zu finden und zu lesen war am 13.9. an elf Stellen implementiert, jede ein wenig anders: sieben kannten nur complete, Detroits Leser nur SUCCESS, der Controller beide; drei uebersprangen versteckte .part-Verzeichnisse, die uebrigen nicht; die Ingestion warf bei kaputtem JSON, der Controller warnte. Als der Controller entstand, musste er jede dieser Eigenheiten einzeln nachvollziehen - und vier der elf Stellen stammten vom selben Tag.

Hier steht es einmal. Was sich je Aufrufer unterscheidet, ist ein Parameter:

  • muster - wo die Manifeste liegen (run_*/manifest.json, ingest_date=*/run_*/manifest.json ...)
  • fehler - welche Ausnahme ein kaputtes Manifest ausloest. Die Ingestion sagt IngestionError, Silver TransformError; ihre Tests haengen an diesen Typen
  • streng - ob ein kaputtes Manifest wirft oder nur gewarnt wird. Fuer eine Pipeline ist es ein Fehler in der eigenen Schicht; fuer den Controller, der nur inventarisiert, eine Warnung

Was nicht hierhergehoert: detroit_pipeline.bronze_manifest.validate_manifest. Das ist kein Leser, sondern ein Zulassungstor mit Pruefsummen, Zeilenzahlen und Schema-Fingerabdruck. Es prueft, ob ein Lauf gilt - hier wird nur gefunden, ob er fertig ist.

 70    liegt, existiert ``verzeichnis`` lokal nicht.
 71    """

 77    @property
 78    def run_id(self) -> str:
 79        # Chicago, Census, NOAA: run_id. Detroit: pipeline_run_id.
 80        return str(
 81            self.manifest.get("run_id")
 82            or self.manifest.get("pipeline_run_id")
 83            or self.verzeichnis.name
 84        )
 85
 86    @property
 87    def begonnen_um(self) -> str:

108            or self.manifest.get("mode")

154# Die Projektwurzel - genannt oder erkannt, nie geraten
155# --------------------------------------------------------------------------
156# Bis zum 6.10.2026 stand an zwei Stellen dieselbe Formel:
157# ``Path(__file__).resolve().parents[3]``. Sie trifft genau einen Fall, die
158# editierbare Installation im Projekt - und raet in jedem anderen. Im Abbild
159# liegt das Paket zwar wieder editierbar unter ``/app``, aber die Formel sagt
160# das nicht, sie zaehlt nur Ebenen. Hier steht sie einmal, und sie prueft
161# ihr Ergebnis, statt es anzunehmen.
162
163#: Die Umgebungsvariable, die die Wurzel ausdruecklich nennt. Das ``Dockerfile``
164#: setzt sie; auf einem Entwicklungsrechner braucht sie niemand zu setzen.
165WURZEL_VARIABLE = "PROJECT_ROOT"
166
167#: Woran eine Projektwurzel erkennbar ist. ``config/`` steht hier, weil die
168#: Stufen ihre Crosswalks **relativ** aufloesen (``--config-root``, Vorgabe
169#: ``config``) - ein Arbeitsverzeichnis ohne sie laesst Gold mit einer leeren
170#: Dimension durchlaufen. ``pyproject.toml`` steht daneben, damit nicht jedes
171#: Verzeichnis mit einem Ordner ``config`` als Wurzel durchgeht.
172WURZELZEICHEN = ("pyproject.toml", "config")

175def ist_projektwurzel(pfad: Path) -> bool:
176    """Traegt dieses Verzeichnis beide Kennzeichen?"""
177    return all((pfad / zeichen).exists() for zeichen in WURZELZEICHEN)

180def projektwurzel(umgebung: Mapping[str, str] | None = None) -> Path | None:
181    """Das Projektverzeichnis - aus der Umgebung oder an der Paketlage erkannt.
182
183    Zwei Quellen, in dieser Reihenfolge:
184
185    1. ``PROJECT_ROOT`` aus der Umgebung. Was dort steht, gilt - und wird
186       geprueft: Zeigt die Angabe auf etwas, das die Kennzeichen nicht traegt,
187       ist das ein Konfigurationsfehler und **kein** Grund, doch wieder zu
188       raten. Dann kommt ``None`` zurueck, mit einer Zeile im Log.
189    2. Die Lage des Pakets. Von diesem Modul aufwaerts, bis ein Verzeichnis
190       beide Kennzeichen traegt. Bei ``pip install -e .`` ist das das Projekt;
191       bei einer gewoehnlichen Installation nach ``site-packages`` findet sich
192       keines - und genau dort log die alte Formel falsch.
193
194    ``None`` heisst *nicht ableitbar*. Wer die Wurzel braucht, bricht damit ab
195    und sagt, was zu setzen ist (``orchestration.run_all``); wer sie nur
196    gebrauchen koennte, laeuft ohne sie weiter (``code_stand``).
197    """
198    umgebung = os.environ if umgebung is None else umgebung
199    genannt = (umgebung.get(WURZEL_VARIABLE) or "").strip()
200    if genannt:
201        wurzel = Path(genannt).expanduser()
202        if ist_projektwurzel(wurzel):
203            return wurzel.resolve()
204        LOG.error("%s=%s traegt nicht %s - die Angabe wird nicht ersetzt.",
205                  WURZEL_VARIABLE, genannt, " und ".join(WURZELZEICHEN))
206        return None
207    for kandidat in Path(__file__).resolve().parents:
208        if ist_projektwurzel(kandidat):
209            return kandidat
210    return None

213#: Die Umgebungsvariable, aus der der Commit kommt, wenn Git nichts hergibt.
214#: Das ``Dockerfile`` nimmt ihn als ``ARG GIT_COMMIT`` entgegen und setzt ihn
215#: hier hinein. Ohne diesen Weg stuende in jedem Manifest aus dem Container
216#: "welcher Code das erzeugt hat: unbekannt" - denn ``.git/`` gehoert nicht
217#: ins Abbild (FR-2), und ein Projekt, dessen Kern die Belegbarkeit ist, darf
218#: die Herkunft nicht fuer eine Zeile in der ``.dockerignore`` hergeben.
219COMMIT_VARIABLE = "GIT_COMMIT"
220
221
222def aus_der_umgebung(umgebung: Mapping[str, str] | None = None) -> str | None:
223    """Der Commit aus ``GIT_COMMIT`` - oder ``None``, wenn dort nichts Gueltiges steht."""
224    umgebung = os.environ if umgebung is None else umgebung
225    genannt = (umgebung.get(COMMIT_VARIABLE) or "").strip().lower()
226    if not genannt:
227        return None
228    if re.fullmatch(r"[0-9a-f]{40}", genannt):
229        return genannt
230    LOG.warning("%s=%s ist keine volle Commit-Kennung - die Herkunft bleibt leer.",
231                COMMIT_VARIABLE, genannt)
232    return None

235@lru_cache(maxsize=1)
236def code_stand() -> dict[str, Any]:
237    """Welcher Code diesen Lauf erzeugt hat - Commit und Sauberkeit.
238
239    Das ist die **forensische** Haelfte der Frage *"ab wann wurden die Daten
240    anders geladen?"*: Der Commit sagt genau, welcher Code lief. Was er nicht
241    sagt, ist ob sich die **Bedeutung** geaendert hat - er springt auch bei
242    einem Tippfehler im Kommentar. Dafuer gibt es ``contract_version``.
243
244    ``dirty`` ist wichtiger, als es aussieht: Ein Lauf aus einem veraenderten
245    Arbeitsbaum laesst sich aus dem Commit allein **nicht** nachbauen. Wer
246    das spaeter wissen will, findet es hier statt es zu vermuten.
247
248    Drei Wege, in dieser Reihenfolge:
249
250    1. **Git.** Wo ein Repository liegt, ist es die beste Quelle - es kennt
251       auch den Arbeitsbaum und damit ``dirty``.
252    2. **``GIT_COMMIT`` aus der Umgebung.** Der Weg des Abbilds: ``.git/``
253       bleibt draussen, der Commit kommt beim Bau als Argument herein.
254       ``dirty`` ist dann ``False``, und das ist keine Annahme, sondern die
255       Lage - ein Abbild hat keinen Arbeitsbaum, der abweichen koennte. Dass
256       das Abbild aus einem sauberen Stand gebaut wird, sichert der Bau in CI
257       zu (FR-3), nicht dieses Modul. Verlangt wird eine volle SHA-1 aus
258       vierzig Hexstellen: Eine Kurzform oder ein Markenname ("v1.2") sieht
259       nachschlagbar aus und ist es nicht.
260    3. **Nichts von beidem** - installiertes Paket, fremdes Abbild, kein git
261       im Pfad: ``None``. Ein Lauf darf daran nie scheitern, und deshalb
262       steht hier keine einzige Zeile, die werfen kann.
263    """
264    wurzel = projektwurzel()
265
266    def git(*argumente: str) -> str | None:
267        if wurzel is None:
268            return None
269        try:
270            fertig = subprocess.run(
271                ["git", "-C", str(wurzel), *argumente],
272                capture_output=True, text=True, timeout=10,
273            )
274        except (OSError, subprocess.SubprocessError):
275            return None
276        return fertig.stdout.strip() if fertig.returncode == 0 else None
277
278    commit = git("rev-parse", "HEAD")
279    if commit is None:
280        mitgegeben = aus_der_umgebung()
281        if mitgegeben is None:
282            return {"git_commit": None, "git_dirty": None}
283        return {"git_commit": mitgegeben, "git_dirty": False}
284    geaendert = git("status", "--porcelain")
285    return {"git_commit": commit, "git_dirty": bool(geaendert)}

288def fingerabdruck(wert: Any) -> str:
289    """Ein Abdruck ueber die Eingaben - derselbe Stand, derselbe Abdruck.
290
291    Kanonisch heisst: sortierte Schluessel. Zwei Tabellen mit demselben
292    Abdruck ruhen auf denselben Eingaben, gleichgueltig in welcher
293    Reihenfolge sie gefunden wurden.
294    """
295    roh = json.dumps(wert, sort_keys=True, ensure_ascii=False)
296    return hashlib.sha256(roh.encode("utf-8")).hexdigest()

303def kennzeichen(wert: Any) -> Any:
304    """Nur die Teile einer Herkunft, die den Eingabestand kennzeichnen.
305
306    Pfade und Bauzeitpunkte fallen weg. Der Grund ist der gemeinsame
307    Speicher: Derselbe Stand liegt bei Christian unter ``/Users/...`` und bei
308    Artan anderswo, und ein zweiter Bau aus denselben Eingaben findet zu einer
309    anderen Uhrzeit statt. Beides darf den Abdruck nicht veraendern, sonst
310    traegt derselbe Stand zwei Abdruecke und die Zusage ist wertlos.
311
312    Was bleibt, ist das Kennzeichnende: Lauf-Kennungen, Pruefsummen und die
313    Abdruecke der Vorgaenger.
314    """
315    if isinstance(wert, dict):
316        return {k: kennzeichen(v) for k, v in wert.items() if k not in FLUECHTIG}
317    if isinstance(wert, list):
318        return [kennzeichen(v) for v in wert]
319    return wert

327def datei_hash(pfad: Path) -> str:
328    """SHA-256 einer Referenzdatei - fuer Crosswalks und Codelisten.
329
330    Ein Pfad sagt nur, *wo* etwas lag. Wer eine Zahl erklaeren will, braucht
331    aber, *was* dort stand: Die Crosswalks werden aus amtlichen PDFs erzeugt
332    und koennen sich aendern, ohne dass der Pfad sich aendert.
333    """
334    h = hashlib.sha256()
335    with pfad.open("rb") as datei:
336        for block in iter(lambda: datei.read(1 << 20), b""):
337            h.update(block)
338    return h.hexdigest()

341def referenz(pfad: Path, manifest: dict[str, Any]) -> dict[str, Any]:
342    """Wie eine abgeleitete Tabelle genannt wird, wenn eine andere auf ihr ruht.
343
344    **Ein Pfad ist keine Version.** ``data/silver/dataset=crime_offense/
345    part-0001.parquet`` zeigt auf das, was gerade dort liegt; wird Silver neu
346    gebaut, zeigt derselbe Satz auf etwas anderes, und nichts verraet es.
347    Deshalb nennt eine Referenz auch **wann** jener Stand gebaut wurde, auf
348    **welchen Eingaben** er ruhte (``input_fingerprint``) und - woertlich -
349    dessen eigene Herkunft. Damit ist die Kette im Manifest selbst
350    verschachtelt: Gold nennt Silver, Silver nennt die Bronze-Laeufe.
351
352    Das ersetzt keine Historisierung der Dateien. Es macht die Frage
353    beantwortbar, aus welchen Eingaben eine Zahl entstanden ist - und das ist
354    die Frage, die in einer Abgabe gestellt wird.
355    """
356    eintrag: dict[str, Any] = {"path": str(pfad)}
357    for schluessel in ("built_at_utc", "input_fingerprint"):
358        if manifest.get(schluessel):
359            eintrag[schluessel] = manifest[schluessel]
360    if manifest.get("derived_from") is not None:
361        eintrag["derived_from"] = manifest["derived_from"]
362    return eintrag

370def versteckt(pfad: Path) -> bool:
371    """Ein ``.part``- oder ``.partial``-Verzeichnis ist ein Lauf, der noch nicht gilt.
372

374    jeder Lauf versteckt, und der Leser meldete stumm: nichts da.

395def fertige_laeufe(
396    wurzel: Path,
397    muster: str = f"**/run_*/{MANIFEST}",
398    *,
399    streng: bool = True,
400    fehler: type[Exception] = ManifestFehler,
401    status: frozenset[str] = FERTIG,
402) -> list[Lauf]:
403    """Alle fertigen Laeufe unter ``wurzel``, nach Pfad sortiert.
404
405    Nach Pfad sortiert heisst bei ``run_<UTC-Zeitstempel>``: der letzte ist der
406    juengste. Versteckte Verzeichnisse zaehlen nie. Ein Lauf, dessen Manifest
407    nicht ``fertig`` sagt, wird mit Warnung uebersprungen - er liegt da, gilt
408    aber nicht.
409    """
410    if not wurzel.exists():
411        return []
412    laeufe: list[Lauf] = []
413    for pfad in sorted(wurzel.glob(muster)):
414        if versteckt(pfad):
415            continue
416        manifest = read_manifest(pfad, streng=streng, fehler=fehler)
417        if manifest is None:
418            continue
419        if str(manifest.get("status", "")).lower() not in status:
420            LOG.warning("Lauf uebersprungen, nicht fertig: %s", pfad.parent)
421            continue
422        laeufe.append(Lauf(pfad.parent, manifest))
423    return laeufe

426def tabellen(
427    data_root: Path,
428    schichten: tuple[str, ...] = ("silver", "gold"),
429    *,
430    fehler: type[Exception] = ManifestFehler,
431) -> list[Tabelle]:
432    """Jede gebaute Tabelle unter den Schichten, nach Schicht und Name sortiert.
433
434    Gesucht wird ``dataset=<name>/**/manifest.json``; liegt eine Tabelle
435    unter einer ``vintage=``, findet der Glob sie trotzdem.
436    """
437    gefunden: list[Tabelle] = []
438    for schicht in schichten:
439        wurzel = data_root / schicht
440        if not wurzel.exists():
441            continue
442        for pfad in sorted(wurzel.glob(f"dataset=*/**/{MANIFEST}")):
443            if versteckt(pfad):
444                continue
445            manifest = read_manifest(pfad, streng=True, fehler=fehler)
446            name = next(
447                t for t in pfad.parts if t.startswith("dataset=")
448            ).removeprefix("dataset=")
449            gefunden.append(Tabelle(schicht, name, pfad.parent, manifest or {}))
450    return sorted(gefunden, key=lambda t: (t.schicht, t.name))

187       geprueft: Zeigt die Angabe auf etwas, das die Kennzeichen nicht traegt,

def datei_hash(pfad: pathlib._local.Path) -> str: 
328def datei_hash(pfad: Path) -> str:
329    """SHA-256 einer Referenzdatei - fuer Crosswalks und Codelisten.
330
331    Ein Pfad sagt nur, *wo* etwas lag. Wer eine Zahl erklaeren will, braucht
332    aber, *was* dort stand: Die Crosswalks werden aus amtlichen PDFs erzeugt
333    und koennen sich aendern, ohne dass der Pfad sich aendert.
334    """
335    h = hashlib.sha256()
336    with pfad.open("rb") as datei:
337        for block in iter(lambda: datei.read(1 << 20), b""):
338            h.update(block)
339    return h.hexdigest()

397    wurzel: Path,

399    *,
