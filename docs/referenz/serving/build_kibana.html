serving.build_kibana

Baut die Dashboards - als Code, nicht als Klickarbeit.

python -m serving.build_kibana              # anlegen und pruefen
python -m serving.build_kibana --trocken    # nur zeigen, was entstuende

Warum das nicht im Browser passiert. Ein zusammengeklicktes Dashboard lebt in Kibanas eigenem Index. Es laesst sich nicht lesen, nicht vergleichen, nicht begruenden, und es ist weg, sobald jemand den Container neu aufsetzt. Alles andere in diesem Projekt ist reproduzierbar; ein Dashboard, das es nicht ist, waere die eine Stelle, an der man sich auf einen Zustand verlaesst, den niemand nachbauen kann. Deshalb stehen die Dashboards hier als Beschreibung und werden ueber die Saved-Objects-Schnittstelle angelegt.

Eine Beschreibung, zwei Darstellungen. Jede Tafel sagt einmal, was sie zeigt. Daraus entsteht beides: das Lens-Dokument fuer Kibana und die gleichwertige Elasticsearch-Abfrage. Der Test stellt die Abfrage wirklich und prueft, dass sie etwas zurueckgibt - damit ist nicht nur belegt, dass das JSON angenommen wurde, sondern dass die Tafel auch etwas anzeigen kann. Ein Dashboard, das sauber importiert und leer bleibt, ist der Normalfall bei erzeugten Dashboards; hier faellt er auf.

Was daran teuer war.

Kibana zeigt die letzten 15 Minuten. Unsere Daten enden am 31.12.2024. Ohne timeRestore mit festem Fenster oeffnet sich jedes Dashboard leer, und nichts deutet darauf hin, dass nur der Zeitraum falsch steht. Das Fenster kommt deshalb aus dem Release und nicht aus einer Voreinstellung.

Auf text laesst sich nicht gruppieren. source_offense_description liegt als text mit .keyword-Unterfeld (siehe load_elasticsearch). Eine Tafel, die das Feld direkt gruppiert, importiert anstandslos und bleibt dann leer. feldname haengt das Unterfeld an, und ein Test haelt es gegen die echte Abbildung im Index.

Angenommen ist nicht gerendert. Die Schnittstelle nimmt jedes JSON. Ob eine Tafel wirklich erscheint, haengt daran, dass jeder Verweis der Darstellung auf eine Spalte zeigt, die es gibt - und genau das prueft pruefe_tafel, weil Kibana es nicht tut.

Zwei Sorten Tafel, und die zweite rechnet. Eine Lens-Tafel aus Kennzahl und Eimer kann zaehlen und gruppieren - nicht aber teilen. Eine Rate je 1'000 Einwohner braucht Zaehler und Nenner aus zwei Indizes und eine Division danach; das ist in Lens' Eimersprache nicht sagbar. Dafuer gibt es die Art esql_tabelle: Sie traegt eine Abfrage in ES|QL, Kibana nimmt sie als datasourceStates.textBased an, und LOOKUP JOIN holt den Nenner dazu.

Der stille Fehler dabei ist nicht die Abfrage, sondern der Nenner. Drei Wege fuehren zu einer Zahl, die man hinschreiben kann und die falsch ist, und keiner von ihnen wirft einen Fehler - die vier Bedingungen an RATE_JE_STADT sagen, welche es sind.

 156@dataclass(frozen=True)
 157class Kennzahl:
 158    """Was gezaehlt wird."""
 159
 160    kennung: str
 161    beschriftung: str
 162    operation: str = "count"
 163    feld: str | None = None
 164
 165    @property
 166    def lens_spalte(self) -> dict[str, Any]:
 167        return {
 168            "label": self.beschriftung,
 169            "dataType": "number",
 170            "operationType": self.operation,
 171            "sourceField": self.feld or ZEILEN,
 172            "isBucketed": False,
 173            "scale": "ratio",
 174            "params": {"emptyAsNull": False},
 175        }
 176
 177    @property
 178    def aggregation(self) -> dict[str, Any] | None:
 179        """``count`` ist in Elasticsearch keine Aggregation, sondern der Umfang.
 180
 181        **``unique_count`` schaetzt.** Kibana setzt es auf ``cardinality`` um,
 182        und das ist HyperLogLog: bis zur Genauigkeitsschwelle exakt, darueber
 183        ungefaehr - ohne dass die Kachel es sagt. Die Schwelle wird deshalb
 184        hier gesetzt und nicht der Voreinstellung ueberlassen; ein Test haelt
 185        die tatsaechlichen Werte dagegen.
 186        """
 187        if self.operation == "count":
 188            return None
 189        if self.operation == "unique_count":
 190            return {"cardinality": {"field": self.feld,
 191                                    "precision_threshold": GENAUIGKEIT}}
 192        return {self.operation.replace("average", "avg"): {"field": self.feld}}

 195@dataclass(frozen=True)
 196class Eimer:
 197    """Wonach gruppiert wird."""
 198
 199    kennung: str
 200    beschriftung: str
 201    operation: str          # "terms" oder "date_histogram"
 202    feld: str
 203    groesse: int = 10
 204    intervall: str = "1M"
 205    #: Fuer ``text``-Felder muss das Unterfeld angehaengt werden - sonst
 206    #: importiert die Tafel sauber und bleibt leer.
 207    unterfeld_keyword: bool = False
 208    #: ``"anzahl"`` sortiert die groessten Gruppen nach vorn - richtig fuer
 209    #: *welche Delikte sind haeufig*. ``"schluessel"`` sortiert nach dem Wert
 210    #: selbst und ist Pflicht, wo die Reihenfolge eine Bedeutung hat: Ein
 211    #: Tagesverlauf nach Haeufigkeit sortiert (0, 12, 17, 16, ...) zeigt
 212    #: keinen Verlauf mehr, sondern eine Rangliste.
 213    ordnung: str = "anzahl"
 214
 215    @property
 216    def feldname(self) -> str:
 217        return f"{self.feld}.keyword" if self.unterfeld_keyword else self.feld
 218
 219    def lens_spalte(self, nach: str) -> dict[str, Any]:
 220        """``nach`` ist die Kennzahl, nach der ``terms`` sortiert."""
 221        if self.operation == "date_histogram":
 222            return {
 223                "label": self.beschriftung, "dataType": "date",
 224                "operationType": "date_histogram", "sourceField": self.feldname,
 225                "isBucketed": True, "scale": "interval",
 226                "params": {"interval": self.intervall, "includeEmptyRows": True,
 227                           "dropPartials": False},
 228            }
 229        nach_schluessel = self.ordnung == "schluessel"
 230        return {
 231            "label": self.beschriftung, "dataType": "string",
 232            "operationType": "terms", "sourceField": self.feldname,
 233            "isBucketed": True, "scale": "ordinal",
 234            "params": {
 235                "size": self.groesse,
 236                "orderBy": ({"type": "alphabetical", "fallback": False}
 237                            if nach_schluessel
 238                            else {"type": "column", "columnId": nach}),
 239                "orderDirection": "asc" if nach_schluessel else "desc",
 240                "otherBucket": False, "missingBucket": False,
 241                "parentFormat": {"id": "terms"}},
 242        }
 243
 244    @property
 245    def aggregation(self) -> dict[str, Any]:
 246        if self.operation == "date_histogram":
 247            return {"date_histogram": {"field": self.feldname,
 248                                       "calendar_interval": self.intervall}}
 249        ordnung = ({"_key": "asc"} if self.ordnung == "schluessel"
 250                   else {"_count": "desc"})
 251        return {"terms": {"field": self.feldname, "size": self.groesse,
 252                          "order": ordnung}}

 301    hier ein anderer Name als in der Abfrage, importiert die Tafel sauber und

 307    beschriftung: str

 317    #: liesse sich das nicht erkennen - eine Rate ist auch nur eine Zahl.

 322        return {"columnId": self.kennung, "fieldName": self.kennung,
 323                "label": self.beschriftung, "customLabel": True,
 324                "meta": {"type": self.typ}}

 349@dataclass(frozen=True)
 350class Abfrage:
 351    """Eine Frage in ES|QL - mit den Spalten, die sie zurueckgibt.
 352
 353    **Warum der Nachschlagindex hier geprueft wird und nicht in Kibana.**
 354    ``LOOKUP JOIN`` verlangt, dass der rechte Index mit ``index.mode: lookup``
 355    angelegt wurde. Ist er es nicht, antwortet Elasticsearch mit *„Lookup Join
 356    requires a single lookup mode index"* - und zwar erst, wenn jemand das
 357    Dashboard oeffnet. Der Modus steht an ``load_elasticsearch.Index``; diese
 358    Klasse liest ihn dort und bricht beim Bauen ab statt beim Anschauen.
 359    """
 360
 361    esql: str
 362    spalten: tuple[Spalte, ...]
 363
 364    def __post_init__(self) -> None:
 365        if not self.spalten:
 366            raise LadeFehler(
 367                "Eine ES|QL-Tafel ohne Spalten zeigt nichts an - Lens braucht "
 368                "je Spalte eine Abbildung von Feldname auf Spaltenkennung.")
 369        for name in self.nachschlagindizes:
 370            index = NACH_NAME.get(name)
 371            if index is None:
 372                raise LadeFehler(
 373                    f"'{name}' steht in einem LOOKUP JOIN, ist aber kein "
 374                    f"geladener Index. Bekannt sind "
 375                    f"{', '.join(sorted(NACH_NAME))}.")
 376            if not index.nachschlag:
 377                raise LadeFehler(
 378                    f"'{name}' steht in einem LOOKUP JOIN, wird aber ohne "
 379                    f"index.mode 'lookup' geladen. Elasticsearch lehnt den "
 380                    f"Verbund ab, sobald jemand die Kachel oeffnet - "
 381                    f"nachschlag=True an load_elasticsearch.INDIZES setzen "
 382                    f"und neu laden.")
 383
 384    @property
 385    def nachschlagindizes(self) -> tuple[str, ...]:
 386        """Welche Indizes die Abfrage ueber ``LOOKUP JOIN`` dazunimmt.
 387
 388        Aus der Abfrage gelesen und nicht daneben gepflegt: Eine zweite Liste
 389        waere die Stelle, an der jemand einen Verbund ergaenzt und den
 390        Eintrag vergisst - und dann prueft niemand den Indexmodus.
 391
 392        **Ohne Gross- und Kleinschreibung.** ES|QL nimmt ``lookup join``
 393        ebenso an wie ``LOOKUP JOIN``; ein Muster, das nur Grossbuchstaben
 394        kennt, findet den Verbund dann nicht und laesst den Indexmodus
 395        ungeprueft durch. Genau so liess sich der Waechter umgehen.
 396        """
 397        return tuple(re.findall(r"LOOKUP\s+JOIN\s+(\S+)", self.esql,
 398                                re.IGNORECASE))

 401@dataclass(frozen=True)
 402class Tafel:
 403    """Eine Kachel im Dashboard."""
 404
 405    kennung: str
 406    titel: str
 407    art: str
 408    #: Nur fuer die Lens-Arten. Eine ES|QL-Tafel rechnet in der Abfrage; eine
 409    #: Kennzahl daneben waere eine zweite, die nichts tut.
 410    kennzahl: Kennzahl | None = None
 411    eimer: tuple[Eimer, ...] = ()
 412    breite: int = 24
 413    hoehe: int = 15
 414    #: Die Frage in ES|QL - nur und genau fuer die Arten aus ``ESQL_ARTEN``.
 415    abfrage: Abfrage | None = None
 416    #: **FR-27, die drei Angaben, ohne die eine Zahl irrefuehrt.** Sie stehen
 417    #: als Beschreibung am Lens-Objekt und damit im Informationsfeld der
 418    #: Kachel. ``docs/ausblick.md`` nennt den Grund: *„Ein Dashboard, das eine
 419    #: dieser Entscheidungen still trifft und eine Zahl hinstellt, macht die
 420    #: Arbeit dieses Projekts zunichte."*
 421    #:
 422    #: Fuer die vierzehn vorhandenen Kacheln der drei alten Bretter sind sie
 423    #: zurueckgestellt (reine Zaehlungen und Anteile); Pflicht sind sie fuer
 424    #: jede ES|QL-Tafel. FR-27 ist damit halb erfuellt und nicht ganz.
 425    frage: str = ""
 426    nenner: str = ""
 427    #: Was die Abfrage wegfiltert, je Kachel einzeln - nie ein geteiltes
 428    #: Tupel und nie ein Positionsschnitt daraus. Beides war dieselbe
 429    #: Wurzel: Wer die Reihenfolge aendert, aendert still, was eine andere
 430    #: Kachel als nicht enthalten ausweist.
 431    ausschluesse: tuple[Ausschluss, ...] = ()
 432    #: Was man beim Lesen wissen muss, ohne dass die Abfrage es wegfiltert -
 433    #: "Tatort ist nicht Wohnort", die Abweichung zu den Abgabedokumenten.
 434    #: Getrennt von ``ausschluesse``, weil dort jeder Eintrag einen Beleg in
 435    #: der Abfrage braucht und ein Vorbehalt keinen haben kann.
 436    vorbehalte: tuple[str, ...] = ()
 437    #: Das Jahr, fuer das die Zahl gilt. Pflicht, sobald eine Rate dabei ist:
 438    #: Sechs Jahrgaenge auf einen Jahresnenner ergeben 500,7 je 1'000 - keine
 439    #: zu hohe Rate, sondern keine.
 440    jahr: int | None = None

 442    def __post_init__(self) -> None:
 443        if self.art not in ARTEN:
 444            raise LadeFehler(
 445                f"{self.kennung}: Art '{self.art}' ist nicht entschieden. "
 446                f"Bekannt sind {', '.join(sorted(ARTEN))}.")
 447        if self.ist_karte:
 448            self._pruefe_karte()
 449        elif self.ist_esql:
 450            self._pruefe_esql()
 451        else:
 452            if self.abfrage is not None:
 453                raise LadeFehler(
 454                    f"{self.kennung}: '{self.art}' liest ueber Lens-Eimer, "
 455                    f"eine ES|QL-Abfrage bliebe unbenutzt. Art aus "
 456                    f"{', '.join(sorted(ESQL_ARTEN))} waehlen.")
 457            if self.kennzahl is None:
 458                raise LadeFehler(
 459                    f"{self.kennung}: '{self.art}' braucht eine Kennzahl - "
 460                    f"ohne sie weiss die Tafel nicht, was sie zaehlt.")
 461            if self.art == "zahl" and self.eimer:
 462                raise LadeFehler(
 463                    f"{self.kennung}: Eine Zahl zeigt einen Wert und "
 464                    f"gruppiert nicht.")
 465            if self.art in ("balken", "linie", "ring") and not self.eimer:
 466                raise LadeFehler(
 467                    f"{self.kennung}: '{self.art}' braucht mindestens eine "
 468                    f"Gruppierung, sonst ist es ein einzelner Balken.")
 469        if self.breite > RASTER:
 470            raise LadeFehler(
 471                f"{self.kennung}: {self.breite} Spalten passen nicht in ein "
 472                f"Raster von {RASTER}.")
 473
 474    def _pruefe_esql(self) -> None:
 475        """Was eine ES|QL-Tafel mitbringen muss, bevor sie entsteht."""
 476        if self.abfrage is None:
 477            raise LadeFehler(
 478                f"{self.kennung}: '{self.art}' braucht eine Abfrage - die "
 479                f"Frage steht in ES|QL und nicht in Eimern.")
 480        if self.eimer or self.kennzahl is not None:
 481            raise LadeFehler(
 482                f"{self.kennung}: Eine ES|QL-Tafel gruppiert und zaehlt in "
 483                f"der Abfrage. Kennzahl oder Eimer daneben waeren eine "
 484                f"zweite Beschreibung, die nichts bewirkt.")
 485        # FR-27. Eine Zahl ohne Nenner und ohne Ausschluesse ist genau der
 486        # Fall, den ``ausblick.md`` als "die Arbeit dieses Projekts zunichte
 487        # machen" beschreibt - und sie faellt niemandem auf, denn sie sieht
 488        # aus wie eine Zahl.
 489        if not self.frage:
 490            raise LadeFehler(
 491                f"{self.kennung}: ohne 'frage' sagt die Kachel nicht, was "
 492                f"sie beantwortet.")
 493        if not self.ausschluesse:
 494            raise LadeFehler(
 495                f"{self.kennung}: ohne 'ausschluesse' liest jemand die Zahl "
 496                f"als vollstaendig.")
 497        for a in self.ausschluesse:
 498            # Der Ausschluss muss in **dieser** Abfrage stehen, nicht in
 499            # irgendeiner. Genau das fehlte, als drei Kacheln sich ein
 500            # Tupel teilten (siehe ``Ausschluss``).
 501            if a.beleg not in self.abfrage.esql:
 502                raise LadeFehler(
 503                    f"{self.kennung}: die Kachel nennt den Ausschluss "
 504                    f"'{a.text[:60]}…', ihre Abfrage vollzieht ihn aber "
 505                    f"nicht - '{a.beleg}' steht nicht darin.")
 506        # Eine Heatmap ohne zweite Achse waere eine eingefaerbte Zeile, eine
 507        # mit vier Spalten liesse eine davon unsichtbar. Kibana importiert
 508        # beides klaglos; der Fehler faellt erst beim Oeffnen auf,
 509        # moeglicherweise vor Publikum.
 510        if (self.art == "esql_heatmap"
 511                and len(self.abfrage.spalten) != HEATMAP_SPALTEN):
 512            raise LadeFehler(
 513                f"{self.kennung}: eine Heatmap braucht genau "
 514                f"{HEATMAP_SPALTEN} Spalten (x, y, Wert), die Abfrage "
 515                f"liefert {len(self.abfrage.spalten)}.")
 516        if self.zeigt_rate and not (self.nenner and self.jahr):
 517            raise LadeFehler(
 518                f"{self.kennung}: eine Rate braucht ihren Nenner und ihr "
 519                f"Jahr. Ohne Jahr ist sie keine Rate, sondern ein Quotient "
 520                f"aus sechs Jahrgaengen und einem Jahresnenner.")
 521
 522    def _pruefe_karte(self) -> None:
 523        """Was eine Karte mitbringen muss.
 524
 525        Weder Kennzahl noch Eimer noch ES|QL: Eine Karte verbindet zwei
 526        Indizes und beschreibt das in ihrem eigenen Format. **FR-27 gilt
 527        trotzdem**, und hier besonders - die Karte zeigt eine Rate, und eine
 528        Flaeche ohne Nenner und ohne Jahr ist genau die Zahl, die
 529        ``ausblick.md`` als "die Arbeit dieses Projekts zunichte machen"
 530        beschreibt.
 531        """
 532        if self.kennzahl is not None or self.eimer or self.abfrage is not None:
 533            raise LadeFehler(
 534                f"{self.kennung}: eine Karte beschreibt ihre Frage als "
 535                f"Verbund zweier Indizes. Kennzahl, Eimer oder Abfrage "
 536                f"daneben waeren eine zweite Beschreibung, die nichts "
 537                f"bewirkt.")
 538        if not self.frage:
 539            raise LadeFehler(
 540                f"{self.kennung}: ohne 'frage' sagt die Karte nicht, was sie "
 541                f"beantwortet.")
 542        if not self.ausschluesse:
 543            raise LadeFehler(
 544                f"{self.kennung}: ohne 'ausschluesse' liest jemand die "
 545                f"eingefaerbte Flaeche als vollstaendig.")
 546        if not (self.nenner and self.jahr):
 547            raise LadeFehler(
 548                f"{self.kennung}: die Karte faerbt nach einer Rate und "
 549                f"braucht ihren Nenner und ihr Jahr.")

 565    @property
 566    def erlaeuterung(self) -> str:
 567        """Frage, Nenner, Jahr und Ausschluesse - als Text an der Kachel.
 568
 569        Kibana zeigt die Beschreibung eines Lens-Objekts im Informationsfeld

 592    @property
 593    def spalten(self) -> dict[str, Any]:
 594        """Alle Lens-Spalten - Gruppierungen zuerst, dann die Kennzahl.
 595
 596        Fuer eine ES|QL-Tafel sind es die Spalten, die die Abfrage liefert,

 620    @property
 621    def darstellung(self) -> dict[str, Any]:
 622        """Der Teil, der sagt, welche Spalte wo hingehoert."""
 623        if self.ist_karte:
 624            raise LadeFehler(
 625                f"{self.kennung}: eine Karte hat keine Lens-Darstellung - "
 626                f"ihre Schichten stehen in karte_objekt.")
 627        if self.art == "zahl":
 628            assert self.kennzahl is not None
 629            return {"layerId": self.schicht, "layerType": "data",
 630                    "metricAccessor": self.kennzahl.kennung}
 631        if self.art in ("tabelle", "esql_tabelle"):
 632            return {"layerId": self.schicht, "layerType": "data",
 633                    "columns": [{"columnId": k, "isTransposed": False}
 634                                for k in self.reihenfolge]}
 635        if self.art == "ring":
 636            return {"shape": "donut", "layers": [{
 637                "layerId": self.schicht, "layerType": "data",
 638                "primaryGroups": [e.kennung for e in self.eimer],
 639                "metrics": [self.kennzahl.kennung],
 640                "numberDisplay": "percent", "categoryDisplay": "default",
 641                "legendDisplay": "default", "nestedLegend": False}]}
 642        if self.art == "esql_heatmap":
 643            assert self.abfrage is not None
 644            x, y, wert = (s.kennung for s in self.abfrage.spalten)
 645            return {
 646                "shape": "heatmap", "layerId": self.schicht,
 647                "layerType": "data",
 648                "xAccessor": x, "yAccessor": y, "valueAccessor": wert,
 649                "legend": {"isVisible": True, "position": "right",
 650                           "type": "heatmap_legend"},
 651                # Keine Zahl in jede Zelle: Bei 7 x 24 Zellen sind das 168
 652                # Beschriftungen, die das Muster zudecken, das die Kachel
 653                # zeigen soll.
 654                "gridConfig": {"type": "heatmap_grid",
 655                               "isCellLabelVisible": False,
 656                               "isXAxisLabelVisible": True,
 657                               "isYAxisLabelVisible": True,
 658                               "isXAxisTitleVisible": False,
 659                               "isYAxisTitleVisible": False},
 660            }
 661        reihe = "bar_stacked" if self.art == "balken" else "line"
 662        schicht: dict[str, Any] = {
 663            "layerId": self.schicht, "accessors": [self.kennzahl.kennung],
 664            "position": "top", "seriesType": reihe, "showGridlines": False,
 665            "layerType": "data", "xAccessor": self.eimer[0].kennung,
 666        }
 667        # Die zweite Gruppierung teilt die Reihen auf - genau so entsteht
 668        # "je Monat, getrennt nach Stadt" aus zwei Eimern.
 669        if len(self.eimer) > 1:
 670            schicht["splitAccessor"] = self.eimer[1].kennung
 671        return {"legend": {"isVisible": True, "position": "right"},
 672                "valueLabels": "hide", "preferredSeriesType": reihe,
 673                "layers": [schicht]}

 675    @property
 676    def aggregation(self) -> dict[str, Any]:
 677        """Dieselbe Frage, an Elasticsearch gestellt.
 678
 679        Verschachtelt in der Reihenfolge der Eimer - so, wie Lens es auch
 680        tut. Die Kennzahl haengt innen, ausser sie ist ``count``: Den liefert
 681        jede Ebene als ``doc_count`` mit.
 682
 683        **Fuer eine ES|QL-Tafel gibt es die nicht**, und das wirft, statt
 684        ``{"size": 0}`` zurueckzugeben. Eine leere Aggregation waere der
 685        gefaehrlichere Weg: ``test_jede_tafel_bekommt_auch_wirklich_daten``
 686        stellte sie, bekaeme Treffer, und die Kachel waere damit als
 687        "zeigt Daten" durchgewinkt, ohne dass die Abfrage je gelaufen ist.
 688        """
 689        if self.ist_esql:
 690            raise LadeFehler(
 691                f"{self.kennung}: eine ES|QL-Tafel fragt ueber /_query und "
 692                f"nicht ueber /_search - ihre Abfrage steht in "
 693                f"'abfrage.esql'.")
 694        innen: dict[str, Any] = {}
 695        if (kz := self.kennzahl.aggregation) is not None:
 696            innen = {self.kennzahl.kennung: kz}
 697        for eimer in reversed(self.eimer):
 698            innen = {eimer.kennung: {**eimer.aggregation,
 699                                     **({"aggs": innen} if innen else {})}}
 700        return {"size": 0, "aggs": innen} if innen else {"size": 0}

1141def pruefe_tafel(tafel: Tafel) -> None:
1142    """Zeigt jeder Verweis der Darstellung auf eine Spalte, die es gibt?
1143
1144    Kibana prueft das nicht. Ein Verweis ins Leere importiert sauber und
1145    faellt erst auf, wenn jemand das Dashboard oeffnet und eine leere Kachel
1146    sieht - moeglicherweise in der Praesentation.
1147    """
1148    if tafel.ist_karte:
1149        # Eine Karte hat keine Lens-Spalten; ihre eigene Pruefung steht in
1150        # ``karte_objekt`` (Verbundfeld, Geofeld, beide Datenansichten).
1151        return
1152    vorhanden = set(tafel.spalten)
1153    if set(tafel.reihenfolge) != vorhanden:
1154        raise LadeFehler(
1155            f"{tafel.kennung}: Reihenfolge und Spalten stimmen nicht überein")
1156
1157    text = json.dumps(tafel.darstellung)
1158    verwiesen = {k for k in vorhanden if f'"{k}"' in text}
1159    fehlend = vorhanden - verwiesen
1160    if fehlend:
1161        raise LadeFehler(
1162            f"{tafel.kennung}: {sorted(fehlend)} stehen in den Spalten, "
1163            f"werden von der Darstellung aber nicht verwendet - die Tafel "
1164            f"zeigt sie nicht an.")

1176    letzte Anlegen ueberschriebe die anderen. Die Tafel des dritten Bretts

1202            # verschiedene, zeigt die Kachel die eine und der Editor die

1206        }

1380def raster(tafeln: tuple[Tafel, ...]) -> list[dict[str, int]]:
1381    """Legt die Kacheln zeilenweise um, ohne dass jemand Koordinaten pflegt.

1387    gitter, x, y, zeilenhoehe = [], 0, 0, 0
1388    for tafel in tafeln:

1390            x, y, zeilenhoehe = 0, y + zeilenhoehe, 0
1391        gitter.append({"x": x, "y": y, "w": tafel.breite, "h": tafel.hoehe})
1392        x += tafel.breite
1393        zeilenhoehe = max(zeilenhoehe, tafel.hoehe)
