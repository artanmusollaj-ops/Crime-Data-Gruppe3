serving.build_einstieg

Schreibt docs/einstieg.html - die Seite, mit der ein Analyst anfaengt.

python -m serving.build_einstieg
python -m serving.build_einstieg --adressen server         --ziel /app/startseite/index.html

Warum eine Datei und kein Dienst. Die Frage "was liegt hier, und wo frage ich es?" braucht keinen laufenden Prozess. Sie braucht eine Antwort, die stimmt. Dieselbe Bauart wie build_referenz.py und build_architekturbilder.py: lesen, rendern, schreiben. Die Seite oeffnet man mit einem Doppelklick.

Seit dem 12.10.2026 liefert sie auf srv01 zusaetzlich ein nginx aus (urbancrime-start, FR-31). Das aendert nichts an dem Satz darueber: Der Dienst liefert eine fertige Datei, er erzeugt sie nicht und fragt nichts ab. Was er ausliefert, entsteht am Ende des Datenlaufs aus dem Release, das dort wirklich liegt - nicht aus dem des letzten Checkouts.

Warum dieses Modul in serving liegt und nicht unter tools/. Bis zum 12.10.2026 war es ein Entwicklerwerkzeug neben build_referenz. Mit dem ausgelieferten Dienst ist es ein Serving-Artefakt wie build_kibana, load_elasticsearch und pruefe_stand - und es muss hier liegen: .dockerignore haelt tools/ aus dem Baukontext heraus, im Abbild gab es dieses Modul also nicht. Importiert hat es ohnehin nur aus dem Paket und aus der Standardbibliothek; der Umzug kostete keinen Import.

Was darauf steht und was bewusst nicht. Alles auf der Seite folgt aus dem Release - Kennung, Vertragsversionen, Zeilenzahlen, Kennzahlen, Gueteziffern. Nichts davon ist abgeschrieben; alles wird beim Erzeugen gemessen.

Kein Zeitstempel und kein eingefrorener Dienstzustand. Beides waere verlockend ("zuletzt geprueft am ..."), und beides machte die Seite unreproduzierbar: Zweimal erzeugt, zweimal andere Bytes, und ein Vergleich sagte nichts mehr. Schlimmer noch waere ein festgehaltener Dienstzustand - eine Seite, die behauptet, Kibana laufe, weil es vor drei Tagen lief. Fuer alles Lebendige nennt die Seite deshalb den Befehl (serving.pruefe_stand) und nicht sein Ergebnis von gestern.

Die Rate je 1'000 ist nicht neu erfunden. Sie kommt aus gold_pipeline.raten_je_stadt - derselben Abfrage, mit der tests/test_aenderungen.py die Zahl im Aenderungsprotokoll bewacht: nur Delikte in Tracts, die einer der beiden Staedte zugeordnet sind, geteilt durch deren Einwohnerzahl. Eine zweite Definition waere eine zweite Wahrheit.

Und sie nennt ihr Jahr. Ein Release traegt seit dem 4.10.2026 sechs Jahrgaenge. Die Zeilenzahlen der Tabellen sind deshalb der ganze Bestand - das ist die Frage "was liegt hier?" -, die Staedtetabelle dagegen zeigt gold_pipeline.RATENJAHR. Beides auf einer Seite gemischt und beides unbeschriftet waere das eine Versehen, das diese Seite nicht machen darf: sechs Jahre Zaehler auf einem Jahr Nenner ergeben 500,7 je 1'000, und die Zahl sieht aus wie eine Zahl.

281def messe(verzeichnis: Path) -> dict[str, Any]:
282    """Alles, was die Seite zeigt - aus dem Release gelesen, nicht abgeschrieben."""
283    from storage.duckdb import verbinde
284
285    from gold_pipeline import RATENJAHR, raten_je_stadt
286    from storage import parquet_spalten
287
288    gold = verzeichnis / "gold"
289    fakt = gold / "dataset=fact_offense/part-0001.parquet"
290    tract = gold / "dataset=dim_tract/part-0001.parquet"
291    acs = gold / "dataset=dim_tract_acs/part-0001.parquet"
292    con = verbinde()
293    try:
294        datensaetze = []
295        # Lokal mit Absicht: Diese Seite liest ein **eingesetztes**
296        # Release - `release holen --einsetzen` hat es an die festen
297        # Pfade gelegt, bevor dieser Schritt laeuft
298        # (`docker/srv01-datenlauf.sh`). Sie liest daneben `stat()` fuer
299        # die Dateigroesse; das geht nur auf einer wirklichen Datei.
300        for pfad in sorted(gold.glob("dataset=*/part-0001.parquet")):
301            name = pfad.parent.name.removeprefix("dataset=")
302            anzahl = con.execute(
303                f"SELECT count(*) FROM read_parquet('{pfad}')").fetchone()[0]
304            # Nicht ueber DESCRIBE: DuckDB ergaenzt aus dem Pfad zwei
305            # Hive-Spalten, ``dataset`` und ``release``, die in keiner Datei
306            # stehen. Die erste Fassung dieser Seite zeigte deshalb ueberall
307            # zwei Spalten zu viel. Begruendung in ``storage.parquet``.
308            spalten = len(parquet_spalten(pfad))
309            datensaetze.append((name, anzahl, spalten,
310                                pfad.stat().st_size))
311
312        # Die Staedtetabelle steht in gold_pipeline.raten_je_stadt. Hier stand
313        # bis zum 3.10.2026 eine Kopie mit dem Kommentar "dieselbe Abfrage wie
314        # in tests/test_aenderungen.py - eine Definition". Zwei Fassungen sind
315        # keine Definition; seit Vertrag 6 waeren es neun gewesen. Der
316        # Jahresfilter steckt mit darin, seit ein Release sechs Jahrgaenge
317        # traegt.
318        staedte = [
319            (z[0], z[1], z[3], z[4]) for z in con.execute(raten_je_stadt(
320                f"read_parquet('{fakt}')", f"read_parquet('{tract}')",
321                f"read_parquet('{acs}')")).fetchall()
322        ]
323
324        guete = con.execute(f"""
325            SELECT reporting_city,
326              round(100.0 * count(*) FILTER (WHERE geo_status = 'inside_city')
327                    / count(*), 2),
328              round(100.0 * count(*) FILTER (WHERE mapping_status = 'exact')
329                    / count(*), 2),
330              round(100.0 * count(*) FILTER (WHERE mapping_status = 'unmapped')
331                    / count(*), 2)
332            FROM read_parquet('{fakt}') GROUP BY 1 ORDER BY 1
333        """).fetchall()
334
335        zeitraum = con.execute(
336            f"SELECT min(date), max(date) FROM read_parquet('{fakt}')"
337        ).fetchone()
338    finally:
339        con.close()
340    return {"datensaetze": datensaetze, "staedte": staedte, "guete": guete,
341            "zeitraum": zeitraum, "ratenjahr": RATENJAHR}
